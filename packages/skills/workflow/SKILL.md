# 视频制作工作流

这个 skill 做的是**视频**。不管用户说短剧、漫剧、动画、片子，都是同一件事，不用在名字上分岔。

服务对象是不懂制作的小白。他不知道自己缺什么，只知道我想要个视频。

## 旧版还在

`old/` 是上一版工作流（2.7.0「Toonflow 画布制作工作流」：拿到定稿剧本就直接进 Seedance 分集导演写提示词），原样保留给用惯了旧版的人。

- 用户明确说“按旧版来”“用以前那套”，就读 `old/SKILL.md`，按旧版把这件事做完，不和本文件混着用。
- 用户说“以前不是这样的”“怎么不直接写提示词了”这类话，告诉他旧版还在，问一句要不要按旧版走；他点头再切。
- 用户没提旧版，就按本文件。
- 更新或清理这个 skill 时保留整个 `old/` 文件夹，不删、不改。

## 怎么跟他说话

见 `references/responseStyle.md`。

一句话：**引导，不盘问。** 用选项、例子、复述让他自己讲出来，每句话只让他做一个决定。

## 流程

先过一道门，再走三步，顺序不能跳。每步都要在一轮内闭合：给结果或给下一步；不承诺通知，不给预计时间。

**开口先看该不该接。** 按 `references/sopRouting.md` 一判断：情绪、非制作请求、做不到的、材料没到手的，先照那里处理，不进下面三步。

**能推出来的不再问。** 用户第一句话里已经说了的（时长、横竖、有没有素材），复述一遍请他确认，不重复提问。

### 一、确认偏好

读项目目录的 `AGENTS.md`；没有就按 `references/preferences.md` 建一份**待确认**模板，不预填默认值。同一轮读一次当前画布的概览，记下能不能写节点。三件逐项问，一次一个：模型（图片/视频）、画幅（横竖与主比例）、资产与画布组织（默认全部放一个画布，按区域分；另一种是资产一个画布、每集一个画布，用户选了才用）。确认一项写一项，没确认的写“待确认”；只有他说“你看着办”，才落建议值，并说明选了什么、可推翻。**“你看着办”只管正在问的这一项**，下一项照常问；三件以外的生产偏好（素材库、命名、审片）没问过就留“待确认”。三件确认完，再回一句“偏好定了，接下来定画风”。

- 这一片完全不生成画面（只剪辑真实素材，生成只用来做字卡、包装）时，模型记“本片不生成”，画布照默认放一个。
- 用户说“这次先别生成”，是这一轮不生成，不是这一片不生成：模型照样按顺序问；他不想定就记“待确认”，写第一条生成提示词之前再问一次。

### 二、确认画风

先读 `references/globalStyle.md`，再动笔：把用户给的指针收窄成一段中文文字，只出 1 张图确认。不满意就改文字、重出这一张，直到他说可以。确认后写进 `AGENTS.md` 的 `## 画风`，这张图作废。**同一轮做完三件事**：读回 `## 画风`，和他认可的那段逐字比对；在当前画布建画风文本节点（建不了就在回复里说一句“画布写不进，画风先存在 AGENTS.md”）；他没看图、按文字定稿的，在 `## 生产偏好` 记一句“画风：用户未看图确认”。

**画风文字只进资产图提示词。** 视频提示词不贴画风，画面风格由已经固定的参考图带进来；只有一条视频完全没有参考图时，才在开头贴画风文字。

**画风没确认，不写剧本、不列分镜、不展开方案。** 用户催，也只说还差画风这一步。

两种情况这一步改做法：
- **完全不生成画面**：不出确认图，改为确认字卡、字幕与包装的样式（字体、字号、颜色），写进 `## 画风`。
- **实拍为主、生成只补空镜**：画风文字照已有实拍素材的样子写（光线、色调、颗粒），确认图用一张实拍截图对照，生成的补镜才接得上。

### 三、执行 SOP

进 `references/sop/` 对应类目。进之前先判手上有什么（任务 / 想法 / 小说 / 剧本，见 `references/sopRouting.md`），再按该类目的结构、资产、验收做。

**类目在画风确认之后定。** 画风没定之前，不猜写实还是动画、不说走哪类；画风定了，再按 `references/sopRouting.md` 三判类目，用一句人话告诉用户走哪类、为什么。进了 SOP，**先过它第二节「开工必问」，再立故事、写剧本**：已经知道的复述确认；规格类（单集时长、集数、配音怎么出）可以把保守值一次列出来请他点头；方向类一次问一个。这一步没过，不给故事选项，也不自己定时长和集数。

**SOP 就是这一类片子的指南。** 先把选中的那份 SOP 读完，然后每到一个阶段，只读它第六节「方法论调用」里这一阶段列出的 `references/methods/` 文件和节，读到够用为止，不预先全读。方法论文件各自独立、互不引用；SOP 第六节没列的，这一类用不上。

**两类文件不受第六节限制**：写任何生成提示词之前，都读 `references/methods/promptWriting.md`，再读所选模型的结构规则（Seedance 读 `references/methods/formatRules/seedance.md`，MiniMax H3 读 `references/methods/formatRules/minimaxH3.md`，资产图读 `references/methods/formatRules/assets.md`）；写剧本就读 `references/methods/formatRules/script.md`。

**定稿当轮落盘。** 画风、剧本、资产表、每一条提示词，用户认可或你交付的那一轮就写下来：第一步已经看过画布能不能写：能写，每份定稿都同时写工作稿和画布文本节点（名字和位置按 `references/preferences.md`）；写不了，只写工作稿，并且每次落盘都在回复里说一句“画布还没放，先存在工作稿/…”。“还没到那一步”不算写不了。写的是全文，不写“见对话”；一个文件里放几条提示词或几张资产图，每条都是能单独拿去用的全文，不写“同上”。画布节点和工作稿是同一份全文，不缩写、不改写；之后改了其中一处，同一轮把另一处改成一样。新建或重写节点，都从工作稿原样复制全文，不凭记忆重打。写进 `AGENTS.md`、画布节点或工作稿之后，都读回全文和来源逐字比对，有出入就重写，不当成显示问题；发现一处错字，把这一轮写过的节点都核一遍。项目里有状态文件的，每次落盘一起更新。回复里说存在哪，那个位置必须真的打得开。

**没有整集分镜，不写第一条视频提示词。** 用户说“先写第一条看看”，也先把整集分镜写出来落盘（逐镜秒数、核过总长、归好条），再写条 1；这一步不为省篇幅跳过。整集分镜单独交一轮，说一句“分镜好了，下一轮写第一条”，不和条 1 挤在同一轮。归好条的同一轮回资产表，把“待分条后定”按实际条数改掉，出图张数跟着改。

**用户说“接下来呢”“继续”，直接写下一份**，不反问“先出分镜还是先写提示词”“一条条看还是全写完”。

**提示词交稿 = 全文落盘 + 回复里附自查。** 自查照所选模型结构规则里的「交稿自查」清单一项一行写，项数和清单一样（交之前数一遍行数），不合成一段话；“开场｜第一拍”每镜一行。每项一句依据（比如“台词：最快一句 30 字 / 7 秒，约 4.3 字每秒”），没核的写“未核”。自查里写“逐字比过”的，这一轮必须真的读过那个文件；没读就写“未核”。没附自查，这条不算交稿。

## 依据与优先级

**不上网搜。** 只有用户明确让你查（“帮我搜一下”“查查现在的规定”），才联网检索；没查到就在这一轮说一句“没查到，先按出发值做”，不反复重试。其余时候按下面的依据直接做。

冲突时按这个顺序裁决：

1. 用户当场说的
2. **其他已装 Skill** 的规则、宿主自带的说明
3. **本 skill 的 SOP 与方法论**（`references/sop/`、`references/methods/`）；SOP 写的是本类目的取值，两者不一致时本类目按 SOP
4. 通用常识

**SOP 里的数字是出发值，直接按它做。** 标了“有时效”的（模型时长和参考上限），照写着的值往下做；模型界面或说明给了不同的数，按新的算，不为核这些数去联网。

## 画幅

横竖屏、比例、分辨率档都是项目工程偏好，在流程第一步定，记进项目 `AGENTS.md`；不在 SOP 里写死。常见比例（竖屏 9:16、横屏 16:9、方版 1:1）只作参考，选哪个由偏好决定。

## 阶段口径（S0–S7）

全库共用一套阶段名，各 SOP 的第六、七节按这个口径写，细分差别在 SOP 里说明：

| 阶段 | 做什么 |
|---|---|
| S0 | 立项与规格：时长、集数或条数、受众、版本 |
| S1 | 内容：选材、集纲、剧本或脚本（画风已在流程第二步锁定） |
| S2 | 资产盘点：角色、场景、道具，哪些复用、哪些补、哪些只能用真实素材 |
| S3 | 资产图：做板、改板、测试、采用 |
| S4 | 分镜与逐镜提示词：算条数，按所选模型的结构规则写 |
| S5 | 生成与拼接：分条生成、跨条连续性 |
| S6 | 声音与字幕：配音、音效、配乐、字幕 |
| S7 | 验收与交付：按 SOP 清单逐项过，多版本交付 |

## 不要轮询

**任何情况下都不主动轮询。** 轮询就是隔一会儿读一次画布、节点或任务状态，看生成好没好；每读一次都是一次模型调用，白白消耗算力。

画布节点、生成任务、渲染状态，只在四个时点读：

1. 开工时，读一次现状
2. 要基于当前节点改东西之前，读一次
3. 报错、或怀疑被别的操作改过时，读一次
4. 交付前验收，读一次

其余时间不查。

**提交生成之后怎么等：**

- **默认不等。** 提交成功就结束这一轮，告诉用户：“提交了，好了画布上会出来；你看到出来了跟我说一声，我接着往下做。”他下一句开口，再读一次结果。
- **这一轮必须接着用结果**（他说了“出完直接接着做”）：用宿主的沙盒工具执行 `sleep` 按预计时长等（Toonflow 里是 `sandbox`，单次超时上限 60 秒，所以每次最多睡 55 秒，可以连着睡几次），睡够预计时长再读一次。还没好，就按上一条结束这一轮，不再“读一次、睡一次”地循环。
- 不知道要多久、或者没有沙盒工具，按默认不等处理。同一个动作失败一次，先报告或换做法，不连续重试刷新：同一个调用报错，不原样重发；按报错提示改一次参数再试，还错就停下，告诉用户卡在哪。



## 生成前先问

生成消耗算力，**每一次出图、出视频前都要先问用户**，包括画风确认图、资产图、分镜图、样片、成片和失败重跑。

问清三件：生成什么、大概几张或几条、用来确认什么。得到明确同意，再调工具。

- “这一步先出 1 张主角板，看脸和衣服对不对；现在生成吗？”
- “第 2 镜上一版动作崩了，准备重跑一条；重跑吗？”
- 提议生成时先提 1 张或 1 条试，过了再问要不要批量；不一上来就提一整批。要试一条视频，只提这一条真正用到的参考板（看它汇总行里列了哪些参考），不顺带提别的板。资产图也一样：先提最要紧的 1 张（通常是主角板），过了再提下一张或一批。
- 没问就生成算违规；“我先跑着看看”也不行。

## 一个例外

要花钱、要交给别人验收的，甲方标准不清楚时先问一句，不然做完不是他的东西。
即便如此，也给两个具体选项让他挑，别让他凭空描述。
