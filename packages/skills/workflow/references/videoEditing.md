# 原视频编辑与延长

已有视频是本次修改对象时使用。编辑包括替换人物或商品、画面局部增删改和声音调整；延长是向前或向后续接原视频。只处理用户指定范围，不要求重写剧本、重新拆剧情或生成整套资产。已有剧本、时间轴只作为相关依据；若目标改为依据剧情生成新视频，回到主工作流的剧情制作路由。

## 明确操作和素材

- 根据用户要求确定原视频、要改动的对象、动作或声音、涉及的时间段，以及要保留的场景、机位、运动、光线、声音和其他主体。只在关键范围不明时询问；不要虚构原视频内容或承诺背景逐像素不变。
- 换人或换商品时，使用用户提供或已采用的参考素材，写清对应对象、外观及需要保留的动作和遮挡关系。没有实际素材时说明缺项，不虚构引用。延长说明方向、期望总时长和衔接动作；音频编辑区分保留、增加、替换或删除哪些声音。
- 复用当前画布及真实媒体节点。使用画布工具发现端口和节点函数；本地素材通过实际支持的 `node:setVideo`、`node:setImage` 或 `node:setAudio` 绑定工作区内真实文件，再连接视频生成节点。只有节点实际支持时才使用其他素材形式，不把 `asset://` 填进要求工作区相对路径的文件参数。
- 含真人人脸的图像或视频应遵守火山方舟肖像规则，不能作为普通参考直接上传；已授权真人素材需走官方授权与审核流程，素材状态须可用。官方另有部分可信模型原始产物等方式，按其适用条件核实。

### 已授权真人素材

需要使用官方肖像素材库时，先确认用户已授权对应人物及本次素材使用，再发现 `seedanceAssets` 工具的实时 schema。工具使用火山账号 AK/SK，`projectName` 须与视频生成 API Key 对应同一项目。本地素材先由已配置的「阿里云 OSS」插件自动上传，取得 HTTPS 签名地址后入库；OSS 存储凭证和模型 API Key 分别在对应设置中填写，不在对话或工作流文档中记录。

本人认证时调用 `startAuthentication` 获取 `sessionId`，由肖像本人点击工具卡片的认证按钮完成认证；完整认证链接可能包含临时凭证，不请求或记录到对话。再用 `finishAuthentication` 提交该 `sessionId` 查询真实素材组 ID，不能代替本人认证或猜测结果。需要复用素材时用 `listGroups`、`listAssets`、`getAsset` 查询；明确获准入库时用 `createAsset` 提交真实 `groupId`、`mediaType`、可选 `name` 及工作区相对 `path` 或公网 `url`，并等待审核。只把状态为 `Active` 的素材作为生成参考，未完成审核就停止该生成。

按实时工具 schema 调用 `selectAssets`，传入目标 `nodeId` 和 `assets: [{id, mediaType, name?}]`，把选中的官方素材绑定到目标视频节点。它设置的是完整选择列表，修改时保留本次仍需使用的素材；随后读取 `node:getConfig` 的 `config.providerAssets` 和 `providerReferences`，确认素材 ID、类型和引用编号。仅火山方舟模型支持这类引用，提交前还会由服务端重新核对素材状态和项目。工具失败或节点不支持时报告具体阻断，不把官方素材伪装成本地文件或宣称绑定成功。

## 真实引用与配置

先连接实际素材，再调用视频节点的 `node:getConfig`，以 `references` 返回的完整引用表核对本地和官方素材。每项 `id` 是稳定引用 ID，`reference` 是当前 `{{ref N}}` 编号，`dataType` 是类型；本地素材另有来源节点、端口和媒体路径。`ready: false` 表示未就绪，`ready: null` 表示官方素材尚需服务端在提交时审核，不等于审核已通过。不同类型共用编号，未就绪输入也占位；不要按媒体类别自行编号。需要排查来源时再用 `getCanvasEdges`、`getCanvasNodes` 读取连线和输出。旧节点未提供 `references` 时先更新插件，不能猜编号继续生成。

通过 `getNodeTools` 读取节点函数的实际 schema，再用 `node:getConfig` 检查可用模型及与当前引用匹配的模式。沿用用户明确指定或已确认的供应商和模型；否则按画布手册选择满足本次要求的可用模型，不能把节点默认值当成用户选择。模型不支持原视频、所需参考或声音时说明限制，不静默换模型、丢素材或改任务。

用户选择火山方舟官方 Seedance 2.5 时，核对实际返回的 `providerId: "volcengine"`、`modelId: "doubao-seedance-2-5-260628"`，选择适合已连接素材的混合参考模式；`node:setConfig` 的 `other.taskType` 使用 `edit`（编辑）或 `extend`（延长），`other.outputFormat` 可选 `mov` 或 `mp4`。官方推荐编辑和延长使用 `mov`，但须考虑播放兼容性。`auto` 由模型判断任务，`reference` 用于参考生新视频；任务类型仍须与提示词表达一致，否则可能异步失败。

用户选择官方 Seedance 2.0、2.0 Fast 或 2.0 Mini 时，仍使用 `volcengine`，具体模型 ID 以节点查询结果为准。三者输出 4～15 秒 MP4，标准版最高支持 4k，Fast 和 Mini 最高为 720p；图片/视频/音频参考上限为 9/3/3，视频与音频总时长分别不超过 15 秒，音频须搭配图片或视频。编辑与延长意图直接写入提示词，不传 `other.taskType`、`other.outputFormat`，也不套用 2.5 的画幅或时长锁定规则。官方素材库引用继续复用，但须遵守当前模型的素材上限。

编辑时适配器向官方接口传 `ratio: "adaptive"` 和 `duration: -1`；延长自动传 `ratio: "adaptive"`，时长按节点支持的选项设置。`auto` 带视频时也使用 `adaptive` 和 `-1`。这些是供应商请求值，不是节点配置值：**不要向 `node:setConfig` 直接传 `ratio: "adaptive"` 或 `duration: -1`**。编辑时即使节点显示通用比例或时长，实际输出仍由原视频决定；官方说明时长可能略短，需核验结果。

官方 Seedance 2.5 最多接受 30 张图片、10 段视频和 10 段音频；所有视频总时长、所有音频总时长分别不超过 30 秒。视频编辑时每段参考视频须为 4–30 秒，其他视频参考为 2–30 秒。官方建议编辑视频不超过 20 秒、参考图使用 1–5 张，这些是效果建议而非额外硬限制。项目本地单个参考文件上限为 100 MB，模型请求体不超过 64 MB；其他格式、尺寸和审核要求以[官方文档](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh)及实际返回为准。

使用本地视频时，先确认阿里云 OSS 插件已启用和配置，再由视频生成链路自动上传；不要先调用 Agent 上传工具重复上传同一视频。上传产生存储和流量消耗，签名地址应覆盖厂商排队与读取时间。任务保留对象键及地址到期时间，签名地址仅在请求中使用。OSS 上传中断后按对象键核对云端结果，不自动重试或删除；已有方舟任务 ID 时只恢复查询原任务。

## 提示词、执行与验收

### 人物与商品替换清单

换人物、商品或其他画面主体时，先分析原视频中目标的全部出现时段，再调用实际注册的 `node:setEditingPlan` 保存清单。不得只检查首帧；回到画面、侧面和遮挡后的再次出现也须覆盖。无法确认的对象或时间段先说明，不编造时间戳。

- `plan.sourceReferenceId`：`getConfig.references` 中待编辑原视频的稳定 `id`，必须是视频。
- `plan.replacements`：每项包含原对象特征 `original`、开始秒数 `start`、结束秒数 `end`、目标图片或视频的稳定 `targetReferenceId`、具体修改范围 `scope`。`end` 必须大于 `start`；同一对象多次出现时分项记录，最多 30 项。按原视频首次出现的顺序组织清单，不能把“换人”自动扩大为换服装、动作或声音。
- `plan.preserve`：保留的动作、遮挡关系、场景、镜头、声音及其他对象。
- `plan: null`：明确不再使用该替换清单时清除，不删除素材或已生成结果。

`original`、`scope`、`preserve` 只填写自然语言描述，不允许包含 `{{ref N}}` 标记；原视频和替换目标通过稳定 ID 绑定，额外素材引用通过 `node:setPrompt` 写入，以免排序后指向错误素材。

清单随画布保存，节点会把每一项按当前引用编号加入实际 `generationPrompt`。通过 `node:setPrompt` 只补充与清单一致的说明，不重复生成另一套对象映射或重述未修改的剧情。工具写入的有效引用立即绑定稳定 ID，后续排序不会改变引用对象；引用被移除时会阻止提交。替换源素材、目标素材或复制节点后，重新读取引用和原素材，核对后再次保存清单；不得为消除错误直接照抄旧清单。节点可检查 ID、媒体路径和类型变化，同路径覆盖文件的内容变化仍须人工或 Agent 重新核对。

保存后回读 `node:getConfig`，检查 `editingPlan`、`editingPlanError`、`promptError` 和完整 `generationPrompt`，逐项核对用户要求。存在错误或 `generationPrompt` 为 `null` 时不得生成；清单的结构与引用校验不代表画面内容或最终效果已经通过验收。清单要求混合参考模式；官方 Seedance 2.5 必须显式设置 `other.taskType: "edit"`。

没有主体替换的增删改、音频编辑与延长，继续使用原有提示词流程，不强制创建替换清单。提示词明确原视频和每个引用的用途、编辑动作、时间段及保留条件；延长写“向前/向后延长”及衔接内容。先核对真实编号再通过 `node:setPrompt` 写入；具体提示词技巧可查看[官方指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)。

生成前展示可审阅的方案：原视频、替换清单（如有）、完整 `generationPrompt`、引用及顺序、模型、模式、参数、输出格式和次数；费用或算力无法查询时明确说明未知。沿用覆盖该具体方案的明确授权，否则先取得授权；参考、参数或次数变化后核对授权是否仍适用。生成前回读节点与配置，保留原视频和已有采用结果，再调用实际可用的 `node:generateVideo`；启动状态不代表生成成功。

通过实际注册的状态工具或节点输出核实结果和来源，不确定提交结果时先查询，不能盲目重试。按实际可查看的能力对比原视频与结果，检查场景、镜头和人物连续性、被替换对象的遮挡、商品包装文字与 Logo、时长及音轨；不能查看或听到的部分明确说明，请用户预览。结果是否采用由用户决定，保留原件和候选版本。
