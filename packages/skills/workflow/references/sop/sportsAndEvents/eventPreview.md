# 赛事预告

判据：**静音只看画面上的字，能不能说出"谁打谁、几号几点、在哪看"。** 三样缺一样就是废片。影视预告藏的是结局；赛事预告藏的是还没发生、而且可能变的东西——倾向、首发、伤情、结果。所以多一道工序：给什么、藏什么、怎么标"这是预测"。

## 一、适用 / 不适用

- 适用：赛前 1–7 天的单场前瞻、系列赛与联赛轮次预告、开票与报名、赛事周预告；短版 30 秒、长版 60 秒。
- 不适用：赛后回顾 → `eventHighlights.md`；球迷情绪向 → `fanSupport.md`；现场开场片 → `documentariesAndEvents/eventOpening.md`；影视、剧集预告 → `musicAndMotion/trailer.md`。
- **赛程天天变**：对阵卡、赛程图、落版三件做成可替换图层，改期只换字不重做。

## 二、开工必问

一次一个。第 3 题决定边界——没确认的一律不给，给了又被证伪，比不给更伤。

1. 时间、地点、观看方式定了吗？会不会改期？——会改期就先只做"待定"版。
2. 观众看完必须知道哪三件事？——写成三句。
3. **哪些信息不能给**：首发、伤情、内部消息、交易传闻？
4. 手上有哪些往期画面、队徽、球员图？——决定哪些用实拍、哪些用中性图形。

答不上来落保守值：短版 30 秒、只给已确认的信息、队徽用自制中性图形，说明可推翻。

## 三、规格

| 项 | 短版 | 长版 |
|---|---|---|
| 时长 | 30 秒 | 60 秒 |
| 首帧 | 0 秒即出现对阵或时间，不做台标动画 | 同左 |
| 片段长度 | 1.5–3 秒 | 2–5 秒 |
| 落版停留 | ≥ 2 秒 | ≥ 3 秒 |
| 表述边界 | 预测带"预测""目前格局"限定词，只提问不下死结论 | |

## 四、结构

| 段落 | 短版 | 长版 | 占比 | 这一段要完成什么 |
|---|---|---|---|---|
| 引子 | 0–3 秒 | 0–6 秒 | 0–10% | 一个动作或一次对峙，配一句问题；不出台标 |
| 对阵背景 | 3–9 秒 | 6–18 秒 | 10–30% | 谁打谁、什么赛事、什么阶段 |
| 看点 | 9–21 秒 | 18–42 秒 | 30–70% | 短版 2 个、长版 3 个看点，每个 1–2 个片段作证据 |
| 赛程与对阵图 | 21–27 秒 | 42–54 秒 | 70–90% | 时间、地点、观看方式、晋级路径；这一段必须可替换 |
| 一个问题收尾 | 27–30 秒 | 54–60 秒 | 90–100% | 抛一个具体问题，不给答案 |

三条硬约束：信息分三层——必知（时间、对阵、入口）、加分（状态、交手、已公开伤情）、不要（数据堆、长语录、未证实传闻）；只提问不下结论（"这套防守能在季后赛活下去吗"可以，"他们必输"不行）；得分连击用快剪，对阵图、数据对比给足时间读。

## 五、资产清单

| 资产 | 要不要 | 合格标准 |
|---|---|---|
| 对阵卡与赛程图 | 必须 | 分层可替换，角落标"更新日期"；核心资产 |
| 队徽与球队色 | 有就用 | 矢量图或自制中性图形 |
| 球员图与历史画面 | 有就用 | 与对阵双方匹配 |
| 数据表 | 必须 | 战绩、排名、交手记录，每项标核对日期 |
| 时间地点与入口 | 必须 | 逐字校对 |
| 落版模板 | 必须 | 日期、地点、入口三行 |

必须做的是"信息清单"，不是气氛板。生成只补氛围、转场、数据条底；不生成比赛画面、球员脸、队徽。

## 七、制作流程

| 阶段 | 本类目做什么 | 产出 |
|---|---|---|
| S0 | 信息三层表 + 时长版本 | 规格 |
| S1 | 一句问题 + 看点 + 片段证据 | 脚本 |
| S2 | 会变的东西逐项标核对日期与负责人 | 信息表 |
| S3 | 对阵卡、赛程图、落版（可替换图层） | 图形资产 |
| S4 | 补镜提示词（可空） | 补镜清单 |
| S5 | 骨架 → 填片段 | 粗剪 |
| S6 | 音效、音乐、字幕卡 | 混音版 |
| S7 | 各比例排版；时间地点入口逐字校；改期预案 | 成片 + 可替换工程 |

## 八、验收清单

- [ ] 时长按第三节
- [ ] 时间、地点、对阵、观看方式逐字校对无误
- [ ] 开头是动作或对峙，且已出现对阵或时间
- [ ] 必知三件事说清，没有堆数据
- [ ] 预测带限定词，无结论式判断；没有把传闻当事实
- [ ] 对阵图有更新日期，是可替换图层
- [ ] 无声可读；落版停留够

## 九、常见失败与修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 把结果写进去了 | 想制造确定性 | 改成问句 |
| 日期或开赛时间错 | 抄了旧截图 | 官方渠道复核 |
| 做成了集锦 | 用高光当主体 | 删掉不支持看点的镜头 |
| 发布时信息已过时 | 做完压了几天 | 落版标更新日期，改期只换图层 |
| 30 秒版塞了三个看点 | 舍不得删 | 30 秒只留 2 个 |
| 对阵卡上的队名用了简称 | 图省地方 | 用官方全称，简称只放在口播 |
| 发布后赛程改了没人管 | 没有负责人 | 信息表里每一项写负责人，改期当天替换图层 |

## 十、示例

示例只演示用法，不是模板，项目内容按实际写。

- 需求："城市业余篮球联赛半决赛，周六晚上打，做个预告。"
- 落值：短版 30 秒；画面用两队往期比赛的自拍素材；队徽用自制的色块编号。
- 信息三层表（S0 的产物）：

| 层 | 内容 |
|---|---|
| 必知 | 12 月 13 日 19:00，某体育馆，A 队对 B 队，现场免费、线上同步直播 |
| 加分 | 两队常规赛 1 比 1；A 队 3 号场均 25 分 |
| 不要 | B 队主力伤情传闻（未证实）；任何比分预测 |

| 时间 | 段落 | 放什么 |
|---|---|---|
| 0–3 秒 | 引子 | 两队上次交手的一次对抗；字幕"上次他们打到了加时" |
| 3–9 秒 | 对阵背景 | A 队对 B 队，半决赛，赢的进决赛 |
| 9–21 秒 | 看点 | 两个：A 队 3 号的突破；B 队的联防 |
| 21–27 秒 | 赛程与对阵图 | 时间、地点、直播入口（可替换图层，角落标更新日期） |
| 27–30 秒 | 一个问题 | "这次谁能撑过加时？" |

最容易错的一处：把伤情传闻当看点。没证实的不说，问题留给比赛。
