# SOP 模板

新增或修改类目 SOP 时照这份写。执行制作时不用读本文件。

SOP 只写**本类目的取值和偏离**。通用做法一律引用 `references/methods/`，不复述：板上不要边缘光、十次测试、尾帧接力的条件、负向怎么写、止损阶梯……这些都已在方法论里写全，SOP 只写"本类目在这里取什么值、哪里和通用做法不一样"。

## 固定结构

```markdown
# {子类名}

{两三句：这一类交付什么；一句话判据。}

## 一、适用 / 不适用

- 适用：……
- 不适用：…… → 去哪个 SOP；不归本 skill 的写明
- **一句话判据**：……

## 二、开工必问

一次一个，按顺序，已知的跳过；最多五问，每问后写"——决定什么"。只问影响片子内容、结构与制作的问题。
最后一句：答不上来时落的保守值，并说明可推翻。保守值只落规格类的值（时长、比例、条数、版本）；决定这是哪部片子的方向（故事、主张、画风）问不出来时，给两版让用户挑，不替他落。

## 三、规格

| 项 | 出发值 | 备注 |
只写决定结构的数：时长、集数或条数、段数、字数、版本。
不写模型时长上限与参考数（引用结构规则的"容量"）；不写死画幅（画幅按项目偏好，只写本类目对画幅的要求，如"竖版要重新构图"）。

## 四、结构

| 段落 | 时长 | 占比 | 这一段要完成什么 |
一张基准时长的表，区间首尾相接、从 0 到 100%；其他时长一句话按占比换算。
三条硬约束。

## 五、资产清单

| 类型 | 数量 | 必须做板 | 说明 |
一句话写清：哪些生成、哪些用真实素材、哪些绝不生成。

## 六、方法论调用

以下文件都在 `references/methods/`。
| 阶段 | 读 | 本类目怎么用 |
按 S1 / S2–S3 / S4 / S5 / S6 列；"读"写到节，"怎么用"只写本类目的取值或偏离。
最后一句：本类目用不上的方法。

## 七、制作流程

| 阶段 | 本类目做什么 | 产出 |
S0–S7 八行都在。某阶段本类目不做，写"不做"和原因。

## 八、验收清单

- [ ] 可检查的条目；数字与第三、四节一致

## 九、常见失败与修法

| 症状 | 原因 | 修法 |
只写本类目特有的；通用失败（换脸、越轴、平光、口型漂……）不写，去 [生成与返修](../methods/generationAndRevision.md) 二。

## 十、示例

开头一句：示例只演示用法，不是模板，项目内容按实际写。
- 需求：用户原话一句
- 落值：第二节问完后定下的规格
- 一句话：本类目的判据落到这个例子上是什么
- 结构落地：按第四节基准时长，逐段写出这一条实际放什么画面和声音
- 第一份产出：本类目 S1 或 S4 的关键产物（提示词开头、镜卡、证据表、拍点表、步骤卡……），只写一小段
- 最容易错的一处：这个例子里最可能翻车的地方和对策
```

## 写作规则

1. **不复述方法论。** 想写一条通用规则时，先查它在不在方法论里；在，就在第六节引用；不在，先补进方法论，再引用。
2. **同一个数只有一个值。** 第三、四、七、八节里同一项的数字必须一致；时间码区间首尾相接。
3. **真实与生成分开。** 纪实、宣传、电商、赛事这类真实性优先的类目，写清生成只补什么；不用生成的人脸、读数、现场冒充真实。
4. **示例要和本文数字一致。** 第十节的时间码落在第四节的区间里，规格落在第三节的范围里；示例里出现的提示词遵守所选模型的结构规则。
5. **人话。** 按 `references/responseStyle.md` 的口气写给执行者看，不写"该方案""维度""闭环链路"。
