# 画布与交付

S5–S7 在 Toonflow 画布上执行时容易出错的几件事：画布怎么读、截断怎么处理、确认/授权/采用怎么分开、提示词怎么当版本文件、台账与交付怎么记。

两条总规矩：**不要轮询**（只在开工、改节点前、报错或怀疑被改、交付前四个时点读；提交生成后默认结束这一轮，不反复查状态，必须等时用一次长等待代替反复读）；**生成前先问**。画布与资产的组织、命名、布局按项目 `AGENTS.md`。

## 一、画布怎么读

不读整图快照。四级下钻，读到够用为止：

1. 只取当前画布的**概览**。
2. 按名称、类型或选择状态**定位目标节点**。
3. 已知节点 ID 就**直接读必要字段**；连线只查局部的入边或出边。
4. 要改节点内容时，再去查节点函数与完整字段结构。

- 节点详情默认只给标签、类型、位置；端口、正文、输出要显式选择，字段筛选只在选了对应分组时生效。节点类型可能带运行时前缀，不写死。
- 全图任务分批处理，上下文只留当前批次、摘要和游标。
- 默认复用当前项目与当前画布；有台账时核对绑定。含糊的"继续"遇到多个可能的目标，先问清。新建、切换、重命名成功后，用返回的新 ID，不沿用旧 ID。
- 文本节点正文通过节点函数保存；文件路径从节点实际返回的字段读，不自己拼。
- 写完读回节点全文，和来源文本逐字比对。长文本转写容易出错字（“腋下”写成“脑下”）；有出入就重写这个节点，不当成显示问题。

工具名与上限会随宿主版本变；能沿用的是这个顺序和边界。

## 二、截断不是证据

截断是正常返回，不是失败；但被截断的内容不能当完整证据，回执被截断也不代表只执行了一半。

- 读取按 `hasMore` / `nextCursor` 继续分页；**空结果但 `hasMore` 为真，仍要继续**。保持原查询参数，只换游标；游标失效就重新查。
- 总量字段是画布总量，不是命中数；选择状态是现场筛选，不是冻结快照。
- 节点内字段被截断时，只查这个节点，用该项自己的路径与偏移续读，不带原游标；没有下一偏移就表示到头了。
- 批量操作先去重，并按宿主当前的每批上限分批（以工具说明为准）。
- 结构操作的 ID 回执可能被缩略。这只影响返回的列表，不表示只完成了一部分；**不为拿完整回执重复执行写操作**（会执行两次），改用只读工具核对。

## 三、确认、授权、采用分开记

三种决定，任意两种都不能替代第三种：

**内容确认**：展示实质的阶段成果（剧本、资产方案、分镜），问要不要调整。用户已明确批准的内容和连续制作范围直接沿用，不把每个工具调用变成提问。

**生成授权**：生成前准备好可审阅的方案，六项齐全——**对象与数量、模型、完整提示词、实际参考、规格、执行次数**。对用户用人话说三件：生成什么、几张或几条、用来确认什么，再加一句"会消耗算力"（查得到就说多少，查不到就说"算力消耗未知"）；其余几项写进台账，他要看再给，不逐字念模型名和参数。同一方案或同一批次不逐节点重复问；新增数量、改了方案、额外重试，都要重新核对授权。普通的"继续"、沉默、表单失败，都不算新的授权。

**结果采用**：记录"采用决定 + 问题反馈 + 结束状态"。工具返回成功不等于验收通过：读图要核身份、数量、必要视角、服装与物件、可读文字。文件路径、播放器、文件存在或一张静帧，都不证明看过全片、听过音轨；核不了的部分如实说，请用户预览并反馈。

**执行前再读一次现场**：用户回复授权之后、真正执行之前，再读一次画布与配置，比对授权的那六项。仍匹配就执行；对不上的重新展示差异、重新确认。不拿"已确认"去执行界面后来被改过的配置。

**确认绑快照，不绑可变正文**：提交审阅时保存这一版的独立快照并展示这一版；等待期间正文被改，原确认仍只对应提交的那一版，列明差异。原稿没有快照的，标"版本依据待核实"，不拿当前文件冒充旧版。

生成失败后不查原因直接重试，是最贵的错误——它会重复消耗算力。先判断错在哪一层（身份、光学、光、动作、空间、表演、声音），再决定改词、改参考还是改参数。

## 四、提示词是版本化文件

一条提示词是一份文件，不是一次即兴。工作稿分四段，只有最后一段进生成：

| 段 | 写什么 |
|---|---|
| 元数据 | 这一镜要什么、模型与参考模式、平台外置项（时长、画幅、参考模式，不进正文）、版本号 |
| 失败记录 | 一行一条："v2 问题 1：症状。改法：确切改了什么。" |
| 补丁日志 | 每条以块名开头："激活参考：改成只控脸 + 完整外观"；结尾写"其余各块逐字未改" |
| 定稿 | 只留能直接粘贴的那一段 |

- **一次只改一行**：下一版除了被点名的块，与上一版逐字相同；改完答得出"改前是什么、改后是什么"。
- 批注和失败记录绝不混进定稿段——模型会把编辑意见当画面描述。
- 整体重写是另一种失败：会把已经起作用的部分一起丢掉。

**一镜一行的版本日志**：版本号、改了什么、判定（过 / 不过，不写评语）。从上一版定稿加一行改动，能还原任意一个"过"的版本。只存最新版就回不去；日志只写在聊天里，换个人接手就断。日志里标明这一轮是"同词重抽"还是"改写"，两者分开数。

## 五、台账与交付

跨轮制作用一个简洁的状态文件加一个画布总览节点，记事实与索引；专业正文仍在各自节点，不复制进台账。优先沿用项目已有的台账。只有存在实际成果时才加记录，不预建空表。

| 表 | 字段 | 什么时候记 |
|---|---|---|
| 成果 | 标识、用途/场次、版本、画布/节点、正文或媒体路径、采用的固定版本、输入依赖、状态与确认依据 | 任何交付物产生后 |
| 生成尝试 | 尝试标识、资产/片段与节点、提示词快照、模型与完整参数、参考文件及顺序与用途、授权范围与剩余次数、返回与实际文件 | 每次生成前后 |
| 片段采用 | 片段与剧情范围、所用生成尝试、采用决定与拟用区间、实际结束状态、已检查/未检查项、后续依赖 | 每次决定采用时 |
| 交付 | 实际交付文件与索引、已生成/已采用/已合成/已归集的范围、缺项与继续所需输入 | 报完成或交付时 |

声称存在的路径必须来自真实的读取、写入或节点返回。本地尝试标识只是记录，不能当成宿主没返回的任务 ID。

**交付时分清四种状态**：已生成的片段、用户采用的片段、已合成的成片、已归集的副本。没有合成或导出工具时，如实交付现有成果和缺项，不说"已完成成片"。生成状态显示"进行中"只表示已开始，不能宣称完成；这一轮等不完，按"一轮一结"说清现状和接入口。

多版本交付（主片、切片、竖版、无声版）逐版验收，每版单独成片、单独记录。
