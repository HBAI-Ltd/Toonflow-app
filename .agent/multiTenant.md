# 多租户开发规范

本规范适用于多租户相关的架构、数据源、身份、项目、设置、存储及迁移开发，与根目录 `AGENTS.md` 共同遵守。多租户模式下的分域设置、项目授权和部署边界按本规范执行；原有独立模式继续保持兼容。根规范中的线上资源保护、命名、文件操作入口、路由及测试边界继续适用。

本文件记录开发约束，不代表相关功能已经实现，也不授权一次性实现全部规划。按用户当前明确要求的阶段开发。

需求背景、用户明确要求、设计基线、待定事项及交接时的实现状态见 [multiTenantContext.md](multiTenantContext.md)。开始工作前一并阅读，区分需求共识、技术建议与实际完成内容。

## 产品与部署边界

- 面向商业多租户设计，支持本地、企业服务器和云端部署，不将多租户等同于局域网联机或某台桌面设备共享后端。
- 租户是数据与权限边界，用户是登录身份，设备是接入方式；一个租户可以有多个用户和设备。
- 服务端保留 Web 能力。平台管理员权限与租户业务权限分开；本机 Web、桌面端、手机和远程浏览器统一遵守租户授权。
- 沿用 Bun、TypeScript、ES Modules 和 Express。关系数据通过统一的 Drizzle ORM 入口访问，同时支持 SQLite 与 MySQL 8.0，不因部署环境另写一套业务逻辑。
- 同一部署保持一个 Bun 进程、一次 `createApp` 创建的业务应用；私有控制端和 `10888` 创作监听可使用薄传输 wrapper，但都转发同一业务 app，不为主机本人或租户复制第二套后端、配置、模型路由或会话系统。
- 第一阶段允许单实例部署，但身份、项目归属、设置和任务状态的设计必须允许后续多实例、负载均衡及独立 Worker。按实际阶段引入共享会话、队列和事件设施，不提前搭建无需求的集群。

## 包结构与依赖边界

- `packages/multiTenant` 仅为独立包的分组目录，本身不是工作区包，不放总包 `package.json` 或聚合源码入口。其下每个能力目录均是独立工作区包，拥有自己的 `package.json`、公开导出、依赖及类型检查配置：

```text
packages/
  multiTenant/
    db/          # @toonflow/multi-tenant-db：数据源、ORM、模型与迁移
    auth/        # @toonflow/multi-tenant-auth：账号、密码、管理与创作会话
    adminWeb/    # @toonflow/multi-tenant-admin-web：管理后台前端
    userWeb/     # @toonflow/multi-tenant-user-web：创作端账号界面
    sourceMapping/ # @toonflow/multi-tenant-source-mapping：业务数据源映射领域
    models/      # @toonflow/multi-tenant-models：显式模型路由、价格与加密执行快照
    billing/     # @toonflow/multi-tenant-billing：用户钱包、预占与结算账目
    gateway/     # @toonflow/multi-tenant-gateway：统一模型分派与计费编排
```

- `db` 统一管理数据源初始化、ORM 适配、连接生命周期、数据模型、迁移及租户数据访问边界；不得依赖 `apps/server` 的内部模块、路由或 `u.conf`。启动时需要的实际数据目录和宿主能力通过明确参数传入。
- `adminWeb` 与 `userWeb` 通过已授权的服务端接口操作多租户能力，不直接连接数据库、不读取 `dataSource.json`，也不打包数据库驱动、服务端模块或连接凭据。
- `auth` 通过 `db` 的公开导出访问持久化能力，数据库包不反向依赖认证包或宿主。认证业务不塞进数据库脚手架，前端包不依赖这两个服务端包。
- `sourceMapping` 是独立业务领域包，负责业务数据源映射的读取、校验和保存，通过 `db` 公开导出持久化；`@toonflow/multi-tenant-source-mapping/config` 只暴露字段、目标、校验、快照契约与默认值供 UI 复用，不能引入数据库驱动、认证或宿主模块。
- `models` 集中管理显式模型路由、成本与售价、平台专用云凭据及加密执行快照；`billing` 管理 SQL 用户钱包、充值、预占、结算和释放，复用 `models` 的价格契约与 `db` 的原子持久化。两个包的 `./config` 仅提供前端可用的纯契约，不引入服务端领域实现、数据库驱动或秘密。
- `gateway` 是独立模型编排领域包，不是 `packages/multiTenant` 的父总包。统一逻辑模型、来源分派、公开目录、报价、专用云配置、执行快照、请求摘要及预占／完成结算／执行流程；单向依赖 `models` 与 `billing` 底层领域，底层包不得反向依赖 gateway 或宿主。
- `packages/providerWeb` 为独立共享前端包 `@toonflow/provider-web`，通过公开 `formCreate`、模型编辑与供应商表单契约服务创作 Web 和超管后台；纯表单通过 props／events 及宿主注入的解析能力工作，不依赖宿主 Axios、Pinia、设置加载或路由，不将原有大设置面板整体搬入认证前后台。
- 多租户领域逻辑和管理后台专属界面集中在所属独立包，其他目录按实际业务职责逐步增加，不提前建立未要求的模块或空脚手架。
- `apps/server` 负责启动注入、HTTP 适配与路由挂载，通过相应独立包的公开导出接入，必要能力再由宿主 `utils.ts` 暴露；`apps/web` 通过 `@toonflow/multi-tenant-admin-web` 接入后台，不各自复制多租户数据库和权限实现。
- `apps/web/src/main.ts` 只负责通用启动、挂载与错误恢复；多租户会话、登录根界面及后台根界面的接入集中在 `apps/web/src/bootstrap/multiTenant.ts`，原创作 App 初始化放在 `apps/web/src/bootstrap/creation.ts`。认证前不得加载业务设置、MCP 等有副作用的业务初始化，后续新增注册等策略继续放在对应入口，不在 `main.ts` 累积业务分支。
- 跨包调用使用包名及声明的公开导出，不穿透其他包源码，也不再使用原总包 `@toonflow/multi-tenant` 或其子路径。根 `workspaces` 必须包含 `packages/multiTenant/*`，新增包同步登记实际依赖与公开导出。
- `packages/multiTenant` 只保存源码和构建配置；运行时数据源配置、SQLite 数据库等仍放在实际数据目录的 `data/multiTenant/`，不得写入 `db`、`adminWeb` 或包的构建产物目录。

## 已有抽象复用

- `apps/server/src/utils/channel` 是已有的业务渠道入口。账号、钱包、子账号、插件市场、模型目录、供应商来源和社区等能力优先复用 `Channel` 契约、`getChannel()` 及现有 HTTP 适配，不为多租户重建平行的渠道抽象或绕过入口直接请求渠道服务；未要求的业务能力不提前实现。
- 渠道与数据库数据源分别管理：`TOONFLOW_CHANNEL` 选择部署使用的业务渠道，`dataSource.json` 选择 SQLite／MySQL 持久化数据源。宿主渠道通过公开导出接入 `packages/multiTenant` 的相应能力，包内不反向依赖宿主渠道源码。
- 多租户接入时，在已有请求入口按已认证用户与租户解析身份和渠道凭据，沿用请求级参数、令牌与取消信号；不能把全局 `settings.toonflowAccount.token` 当作所有租户的身份，也不能按请求修改部署级环境变量切换渠道。
- `packages/file` 是已有的统一文件基础入口，磁盘操作继续使用 `@toonflow/file` 与 `@toonflow/file/bun`，复用其原子写入、独占创建和路径队列；不在 `packages/multiTenant` 中复制原生文件封装或新增同职责的文件基础包。
- 租户授权、项目路径映射、对象存储适配及跨实例业务协调放在所属业务模块，按需扩展已有入口；不将租户身份、ORM、业务事务或分布式锁混入文件原语，也不因已有文件抽象就假定租户隔离和跨进程协调已经完成。

## 数据目录与首次开启

- 开启多租户时，在应用实际数据目录下创建 `multiTenant` 文件夹；默认目录结构如下：

```text
data/
  settings.json
  multiTenant/
    dataSource.json
    multiTenant.sqlite
```

- 上述 `data/` 指启动入口已经确定的实际数据目录，复用 `TOONFLOW_DATA_DIR` 与现有数据目录定位规则；不依赖 `process.cwd()`，不写入可被更新替换的程序资源目录。
- `data/multiTenant/` 存放多租户启动所需的基础数据源配置及默认 SQLite 数据库。数据源配置固定为 `dataSource.json`，默认数据库文件为同目录的 `multiTenant.sqlite`。
- 首次开启且尚无数据源配置时，创建以下默认配置；`sqlite.file` 相对于 `multiTenant` 目录解析，解析后必须仍位于该目录内：

```json
{
  "provider": "sqlite",
  "sqlite": {
    "file": "multiTenant.sqlite"
  }
}
```

- 未开启多租户时，不因普通启动自动创建多租户目录、数据库或迁移旧数据。
- 首次创建配置使用独占创建；已有配置必须读取和校验，不覆盖、不重置。数据库连接、必要结构初始化及对应阶段要求的初始化数据成功后，才提交开启状态。
- 初始化失败应明确报错，保留已有配置、数据库和已创建内容，支持安全地继续处理；不得以回滚为由自动删除数据库、记录或线上对象。
- 停用多租户保留 `multiTenant` 目录、配置及数据库，不自动合并用户数据到独立模式，也不自动删除租户或项目。
- 宿主启停标记使用 `settings.json` 中的 `settings.multiTenantEnabled`，默认关闭。数据源配置和超级管理员密码哈希不混入宿主设置；普通设置完整保存必须保留服务端当前启停值，只有首次配置及已认证超管接口可以修改。

## 设置页与超级管理员入口

- 首次进入“多租户能力”页面，读取服务端状态；未配置时提供超级管理员账号、密码、确认密码、开启多租户开关和保存操作。账号与密码验证及持久化成功后才能提交开启状态，密码不得明文保存或回传。
- 已配置后，设置页继续保留多租户开关与“进入超管后台”入口，不再次提供首次密码设置。用户已明确选择保留开关，覆盖此前“已配置后仅作为跳板”的方案。
- 超级管理员使用账号与密码登录，不能只验证密码；账号字段为 `userName`，去除首尾空白后为 1–64 字符，不包含内部空白或控制字符。从设置页修改已配置的开关使用同样的账号密码验证，取消或失败保留原状态。
- 用户最新要求覆盖此前“独立后台窗口”的方案：桌面启动时已开启多租户，或运行中首次开启后，主窗口直接显示超管后台。主机模式在当前进程内保持到退出；之后关闭开关仅停止创作服务，主窗口仍留在后台，退出并在关闭状态下重启后才恢复独立创作入口。重载、再次激活和连接切换导航不得意外回到创作主页。
- 主机本人和租户的创作 Web 统一使用 `10888`，复用同一业务应用；私有端口用于控制、adminWeb 与原生接入，不提供创作 API 旁路。`createApp` 只装配应用，桌面／独立启动入口调用同一公开多租户运行时启动和停止监听，不重复创建应用或另起 Bun。
- 开启时隐藏设置中的整个“第三方模型”分组（文本模型、媒体模型）和整个“开发者选项”页面，首次引导中的第三方模型入口同样隐藏；关闭后恢复入口，不能删除已有配置。
- 管理后台位于独立包 `packages/multiTenant/adminWeb`，使用 Vue Router 提供总览、用户管理，并将业务导航分为“模型服务”（供应商管理、模型路由、价格配置）与“平台设置”（系统配置、数据源映射）。平台专用云凭据放在供应商管理，路由绑定与价格各在所属页面维护；路由与组件仍留在后台包，继续复用已有认证、启停及创作入口，不在宿主复制第二套后台业务。
- Windows SDK 将 Ctrl 刷新误判为新窗口时，仅保留后台根、`/multiTenant/overview`、`/multiTenant/configuration`、`/multiTenant/users`、`/multiTenant/sourceMapping`、`/multiTenant/models`、`/multiTenant/providers` 与 `/multiTenant/prices` 的合法 hash，重新构造宿主 URL 并保留 `host=1` 握手标记；其他目标回到后台根，不能退回创作主页。新增后台页时同步调整此白名单。
- 总览和配置只展示真实可得的服务状态、访问端口及创作入口等信息，配置操作使用已有启停接口。本轮已明确授权下方普通账号管理范围，不能继续用旧“未授权用户 CRUD”限制阻断；该授权不包括虚构统计、组织租户 CRUD、成员角色管理、订阅收费、可编辑数据库连接或其他新后端。
- 复用现有 Toonflow Logo 与语义主题变量，支持窄屏导航、深浅主题和长译文；不能因后台改版改变原有认证、主窗生命周期、`10888` 网关或账号隔离边界。管理会话通过 HttpOnly Cookie 恢复，当前进程退出后失效；主窗口重载无需重复登录。管理令牌不放进 URL、宿主设置或浏览器持久缓存，也不在窗口间传递管理令牌。
- 宿主创作端和后台统一复用 `apps/web/src/lib/appearance.ts` 应用主题，不分别维护主题、主色、字号和圆角逻辑。后台从已鉴权的状态接口取得超管身份及主题、语言、主色、字号、圆角等 UI 白名单；不能为同步外观而读取或回传完整主机设置、供应商凭据或其他秘密。
- 原生主机身份必须由本次启动的随机 secret 证明。主窗口 preload 通过 `/api/multiTenant/hostSession` 换取主机 HttpOnly Cookie；打开创作 Web 时，普通 Web 窗口通过 `/api/multiTenant/user/host` 证明同一 secret 后，以超管身份访问旧设置与项目。前端初始化等待 `window.toonflowHostReady`，不向页面暴露 secret，不将其写入 URL、磁盘或持久设置，不把主机管理 Cookie 当作公开创作入口的授权。
- 原生打开的创作窗口保持普通 Web 能力，不授予 RPC；只在明确的本机 `10888` 创作入口执行原生身份兑换。普通浏览器手工访问 `10888` 必须登录，不能依据 loopback、Host、自报标记或客户端提供的账号 ID 自动授予超管身份。
- 创作窗口仅首次成功兑换原生身份时自动登录，后续重载使用 Cookie；显式退出后应返回登录页，不能因 preload 再次执行而自动重登。只用窗口会话中的非敏感标记记录已兑换状态，存储受限时不阻断首次登录，也不改存 secret 或令牌；主窗口的主机身份握手不受创作账号退出影响。
- 兼容首阶段仅设置密码的旧认证表：通过显式配置或登录入口幂等增加账号列，旧账号使用 `admin`，保留原密码和会话；普通状态读取不隐式修改结构，不重置或删除旧表与记录。
- 当前首次配置仅允许受控宿主本机入口，拒绝互联设备和已标记为远程的代理请求；已有密码的后台登录可远程使用。云端公网首次初始化授权流程尚未实现，不将本机检查当作后续租户身份认证。

## 控制端、创作端与原互联边界

- 开启多租户后，私有控制端只开放启动握手、必要 session、自身多租户管理与获准原生能力；无论携带主机管理 Cookie 还是租户 Web Cookie，创作目录、生成、项目、用户创作登录等私有创作路径均返回 `403`，提示通过 `10888` 访问。
- `10888` 只按创作 Web 会话认证主机／租户，拒绝管理接口、旧全局 providers 与平台配置路径，不能因超管角色而开放全部私有能力。主机 Cookie 可能被同主机名的浏览器携带到此端口，但不能作为创作授权；主机必须用受控 proof 经 `user/host` 换取同一 Web 会话协议，普通用户仍正常登录。
- 主机创作 settings 仅包含 `stores`、`ui`、`general`、`privacy`、`helloCompleted`、`agentSystemPrompt`、`agentNodeTools`。保存按此完整白名单范围替换，范围外从现有平台配置保留；不得读写全局模型／云账号、network、MCP、启停等字段，也不将其余平台配置混入创作 DTO。独立模式原协议与普通用户 SQL 设置 CAS 不变，本轮没有新增主机 CAS。
- `utils/multiTenant/mode.ts` 统一提供 `isEnabled` 与 `creationPort`，运行时、模型 gateway 和旧互联防护共用同一开关，不维护会分叉的多套启停状态。开启响应完成、连接关闭或 `500ms` 兜底只通知一次主窗口晋升，避免响应异常时仍停留在创作入口。
- 多租户启动或开启时停止旧 mobileLink listener 与临时配对连接状态，保留 `enabled` 和设备记录，不走将 enabled 改为 false 的暂停配置流程。主机本机多租户或当前进程 sticky hostMode 下忽略旧 mobileConnection active，动态拒绝远端设备切换；关闭后独立模式重启可恢复原连接配置。
- 旧设备互联保留为独立模式兼容能力，不能作为多租户创作端绕过 `10888` 的入口；拒绝 mode/connect/disconnect 等受限切换不得改写连接配置或清除设备记录。以上传输与端口隔离不代表组织租户、多实例或原生平台已全部验证。

## 当前账号隔离阶段

- `10888` 创作入口提供 SQL 持久化的注册、登录和会话；普通账号注册、登录后进入现有创作 Web，设置菜单提供当前账号与退出入口。账号界面集中在独立 `userWeb` 包，不另建第二套创作前端。
- 创作 Web 自助注册由 SQL 平台策略 `registrationEnabled` 控制，默认开启；旧数据库或缺少策略记录时同样按 `true` 兼容。仅已认证超管可通过后台配置页与管理接口修改，不能保存到普通账号设置或依赖前端自行决定策略。
- 匿名创作会话返回 `registrationEnabled` 布尔值供登录页决定是否显示注册入口。关闭后隐藏入口，服务端注册同时返回 `403`；已有账号登录及超管在用户管理中新增普通账号不受影响。关闭注册不删除账号、项目、设置或其他数据。
- 本阶段身份只有超管与普通账号，尚未实现组织租户、成员关系、项目共享或稳定 `projectId` 登记。不能把当前账号隔离表述为完整商业多租户系统或已支持多实例。
- 超管通过 `10888` 继续访问旧项目与获准创作设置，不读取整份平台设置，不自动搬迁、改写或分配旧项目给新账号。普通账号的设置保存在各自 SQL 记录中，只接收允许的用户字段，不能读取或覆盖全局供应商、网络、MCP 等主机配置；保存以 `revision` 条件更新实现 CAS，冲突返回 `409`，不能无条件重试旧快照。
- 普通账号工作区限定在实际数据目录的 `multiTenant/workspaces/<userId>/`，目录列表与文件操作复用统一授权入口。账号身份由已认证会话确定；真实路径、父子边界及符号链接仍须检查，不能因同在服务器上而开放旧项目根或其他账号目录。
- 普通账号在原有已隔离设置、工作区文件与只读能力之外，本轮明确开放显式平台模型目录、文本生成、媒体目录／报价／生成、本人任务状态／取消及本人余额；新增放行使用精确 HTTP 方法与路径。serverAgent、MCP、全局素材、全局供应商管理、平台余额 SSE 等未授权入口继续 `403`，不能因模型路由已接入就开放全部服务端能力。

## 普通账号管理

- 用户已明确要求真实普通账号列表、搜索分页、新增、启用／禁用与重置密码，入口为后台 `/multiTenant/users`。这些操作只允许已认证超管通过管理接口执行；公开创作入口和普通账号不能取得管理权限，也不借此改变超级管理员角色或新增角色分配功能。
- 列表、搜索、分页与总数来自实际 SQL 普通账号记录，不伪造用户、计数或业务指标。历史记录的时间字段为 `0` 时表示未知，不能显示为 1970 年，也不能在迁移时伪造为当前创建时间。
- 禁用是明确的账号登录状态，账号继续出现在管理列表中，不隐藏、不软删除、不删除项目或设置。本轮没有任何账号、数据库记录或线上对象删除授权，不能在重置、禁用或迁移中加入清理。
- 数据库持久化 `authVersion` 安全版本；重置密码、禁用和启用均须原子推进该版本，使已有会话失效。认证同时校验账号启用状态与会话版本；重新启用只允许重新登录，不恢复旧会话。
- 新增与重置继续使用现有账号、密码校验及密码哈希逻辑，不能明文存储或回传密码、哈希与会话凭据。账号管理复用 `db`、`auth` 的公开导出，HTTP 层维持一接口一文件、统一校验和错误响应，不在前端绕过授权操作数据库。

## 业务数据源映射与模型接入边界

- 后台 `/multiTenant/sourceMapping` 仅显示供应商来源、插件和社区三项其他业务草稿，不提供模型草稿开关；模型配置统一进入真实模型路由。SQL 契约仍保留 `models`、`providers`、`plugins`、`community` 四字段以兼容旧记录，保存时保留旧 `models` 字段，不将它用于实际模型分派；目标仍只允许 `backend`／`toonflowCloud`，旧缺省四项云端。这不是 SQLite／MySQL 连接配置，也不替代 `dataSource.json`。
- 映射独立保存在 SQL 表 `multiTenantSourceMapping`，不混入宿主完整设置或注册策略。读取、保存复用领域包与 ORM；保存携带 `revision` 并使用 CAS，旧版本冲突返回 `409`，保留客户端修改，不无条件重试、重置或删除记录。
- 仅已认证超管可访问 `GET /api/multiTenant/sourceMapping/get` 与 `PUT /api/multiTenant/sourceMapping/save`。公开创作网关拒绝管理路径并返回 `403`；普通账号或自报身份不能读取或改写平台映射。
- 用户后续明确授权模型显式路由、价格及余额扣费，覆盖此前“全部只存草稿、暂不计费”的阶段限制。模型请求通过 `gateway` 统一解析已启用显式路由实际处理，`models` 保留底层模型领域职责；`sourceMapping` 快照仍为 `applied: false`，其中供应商来源、插件与社区三项仍仅保存草稿，不能宣称相应业务已切换。
- 不新增云端个人账号映射，不复用全局个人云令牌为所有用户调用上游。上游成本、用户售价与钱包按下方本阶段授权分别实现，不增加在线支付、套餐或其他未要求业务，也不加入空字段和假数据。

## 统一模型网关与宿主边界

- 所有模型入口复用 `@toonflow/multi-tenant-gateway` 的同一编排契约。来源按路由 `target` 注册 `backend`／`toonflowCloud` 的 `ModelSource` 并由网关分派；模型类型使用同一适配器契约声明能力，不为文本、图片、视频、音频重新建立平行的路由或计费门面。
- `apps/server/src/utils/multiTenant/gateway.ts` 仅做 composition：注入实际数据目录、启停读取、来源／协议适配器、专用云解析与加载、价格展示格式。`modelAdapters.ts` 只负责来源、上游协议结构、公开 capabilities、纯参数校验及可信最大用量；入口不得复制价格计算、钱包状态转换、来源选择和计费分支。旧宿主 `multiTenant/models.ts`、`billing.ts` 已移除，不能在其他入口重建同职责实现。
- 管理 HTTP 路由和 `management.ts` 只做身份授权、入参校验与转发，管理、目录、报价、生成和账务统一调用网关。文本通过 `gateway.run` 组合预占、执行和完成处理，不恢复 `reserveTextCharge` 等入口自编排；结算失败不得进入执行失败的退款分支。
- 已认证身份通过服务端 AsyncLocalStorage 传递，在 Agent 模型配置创建时捕获并随 runtime 保留；每个 SDK turn（含摘要、子 Agent、singleAgent、A2A）沿同一 `gateway.run`、可信 usageTracker、报价与 finalize，不因后台继续运行而退回个人凭据或漏记账。singleAgent 复用解析后的 `runtimeModel`，不能按 alias 再走 SDK 默认模型回退；保留 Anthropic thinking 等协议元数据。此内部统一不开放普通账号原本 `403` 的 Agent 路由。
- 网关只投影使用可信 AuthIdentity 的 `id`／`role`，允许其携带 `userName` 等已认证附加字段，不因内部严格对象校验误拒绝真实文本入口；不能从客户端自报字段生成身份或提升权限。
- 网关统一创建加密 execution，冻结路由、版本和上游。请求摘要由网关对 owner、路由 ID／revision、规范化请求及显式 scope 计算，并与 `requestId` 绑定；调用方不自行拼接另一套哈希或重新读取当前来源来改派已提交请求。
- 完成处理通过统一 `ModelOutcome` 证据：可信 `usage` 才结算，明确未提交或失败／拒绝／取消且未交付才可释放；`unknown`、已交付但缺用量或结算失败保留预占。协议适配层提供可信用量与提交／交付证据，网关决定账务动作，不能只按 HTTP 状态或取消信号退款。
- 媒体持久任务继续负责两阶段落盘、工作区授权与输出交付哈希／实际秒数证明，复用同一 `reserveSnapshot`／`finalize`；不再自行决定路由售价、扣费或钱包终态。兼容旧 `modelRouteCipher` 与 legacy request hash 以恢复既有 pending 预占，不读当前路由、当前来源或新价格重新提交旧任务。
- 图片、视频、音频的工具入口统一使用媒体任务 start／wait，不绕过持久任务直接调用生成或供应商报价。任务缺少 `chargeId` 时禁止盲用 `taskId` 释放：必须通过冻结 execution、owner、原 scope／请求哈希及 `recoverExisting` 证明是同一预占，冲突时保留原记录。宿主确认未提交的异常只以进程内 WeakSet 证据释放，不信任供应商自报错误码；unknown 或已交付仍按统一规则 held。
- debug 与独立使用 DeepSeek 凭据的模型搜索在多租户模式下使用动态 direct-access guard 返回 `403`，真正请求前重新检查，不能因跨 await 前处于独立模式而直连。DuckDuckGo／Tavily 非模型搜索保留；受控工具须遵守统一能力入口，但可信第三方工具并不是执行沙箱，不能据此宣称任意插件代码已隔离。
- `apps/server/src/utils/ai/provider.ts` 集中供应商 schema、配置读取、上下文与输出上限、推理档位及协议能力，供 AI 执行与宿主来源适配共同使用；不能重新形成 `AI → multiTenantModels → AI` 的运行时循环依赖。
- 本轮是职责与依赖方向重构，不代表引入队列、分布式执行租约或新的跨实例协调能力。仍遵守现有身份、任务归属、幂等与持久化边界，实际验证按本轮结果单独记录。

## 模型路由、专用云凭据与余额计费

- 后台 `/multiTenant/providers` 维护供应商与平台专用云凭据，`/multiTenant/models` 维护模型路由，`/multiTenant/prices` 维护用户售价与可选上游成本。模型、供应商及账务管理接口仅允许已认证超管，公开创作入口返回 `403`。路由保存使用 `revision` CAS；旧路由 ID 不得移除，只能停用，不删除历史关联与账目。
- 对外别名 `publicId`、内部永久 `route.id` 与真实 `upstreamModelId` 必须分开。例如创作 Web 请求 `qwen8`，经多租户后端路由到实际 `gpt6` 或 Toonflow 云来源；管理员可编辑别名及改绑上游，但不能改变既有路由的内部身份。旧记录未设置 `publicId` 时回退内部 UUID，别名不能重复或占用其他路由的内部 ID。
- 保存仅对新建、新启用或实际 `type/target/providerId/upstreamModelId` 绑定改变的启用路由检查当前上游可用性。既有失效绑定不变时，不能阻止逐条停用、改名或改价；继续保留永久 ID、schema 和 CAS 校验，不能将兼容旧失效记录当作允许新建失效绑定。
- 创作端目录每条路由仅发布一条 `providerId: "multiTenant"`、`modelId: publicId`，并带 `routeId` 供旧 UUID 选择迁移；不能把别名和 UUID 发布为两个重复模型。共享选择逻辑应按旧 `routeId` 找回并迁移到当前 `modelId`，旧供应商／模型配对仍不能绕过网关。新请求按当前绑定解析，历史 execution、价格和任务快照沿原路由 ID／版本恢复，不受改名或改绑影响。
- 文本、图片、视频、音频选择统一复用 `nodeAi`／`modelCatalog`，设置目录也来自同一来源。平台选择保留稳定 `routeId`，真正 HTTP 提交前 fresh 读取目录解析当前 `publicId`；兼容旧 UUID 与仍能关联的当前 alias，离线旧 alias 无法关联到内部路由时明确要求重选，不能猜绑定或静默选其他模型。
- 共享语言／媒体目录采用 `30` 秒 TTL，仅在读取、focus、visibility 或展开时检查，不启 interval 轮询；共享订阅刷新仍挂载的列表与报价。该限制只针对目录，不移除在途媒体任务原有的状态查询。后台改别名／售价后，同一路由选择应随目录更新名称与价格，不强迫重新选择。多租户下关闭旧供应商余额／SSE 与个人云安装的迟到写回，本人 SQL 钱包沿用现有账号 UI，不另建一套余额状态。
- 云凭据、供应商配置和内部执行快照使用 AES-GCM 加密，无个人云令牌回退。公开创作 DTO 不回传平台供应商源码、配置或凭据；私有超管供应商维护可按授权读取和编辑 source／config，不能将公开 DTO 的限制误解为禁止此维护功能。加密主密钥与平台专用云令牌不回传前端。
- MySQL 部署必须配置共享 `TOONFLOW_MULTI_TENANT_SECRET`，其值为 32 字节密钥的标准 Base64；各实例使用同一密钥。SQLite 默认可在实际 `data/multiTenant/modelSecret.key` 独占创建密钥，权限为 `0600`；缺失、损坏或密钥不匹配须明确报错，不自动重置已有加密数据。
- 价格用最多六位小数的十进制字符串传递，以 BigInt 整数微单位计算，币种仅 `CNY`／`USD`，成本与用户售价分开。文本按 `perMillionTokens` 的输入、输出、缓存读取、缓存写入四费率；图片与音频按次，视频按次或按秒。未知必要用量不能当作零，实际扣费超过预占时封顶到预占额，差额由平台承担。
- 平台超管本人不扣内部钱包；普通账号只读取与消费自己的对应币种钱包。管理员在用户管理中给单个普通账号增加余额，金额必须为正，使用 `requestId` 幂等，不支持负值扣减、删账、在线支付或套餐。账号页展示本人余额、预占、可用余额和最近 20 笔安全账目，不回传平台余额、上游成本或内部快照。
- 文本在调用上游前按上下文窗口、最大输出和缓存读取／写入上限保守预占，成功后按实际用量结算并退回差额；失败按已确定状态释放。多租户模型 SDK 自动重试关闭，未知上游结果不得通过自动重发形成重复执行与扣费。
- 媒体任务持久化 `ownerUserId`、`modelRouteCipher` 与 `chargeId`。SQL 与任务文件采用两阶段顺序：先持久化提交意图，再原子预占，再持久化 `chargeId`，最后才允许请求上游。视频按秒时先按请求时长预占，成功后对可信输出探测实际时长再结算。
- `interrupted` 或上游结果未知时保留预占；明确失败／取消且无交付才释放，已有可信用量与交付则按统一 outcome 结算；无法确定时保留预占待处理。恢复只沿用原任务、执行与价格快照并对账，不能换路由重提；预占复用不代表已取得任务执行租约。结算、释放及幂等通过 SQL 原子状态转换，不能把取消请求或中断当作已完成退款。
- 超管可在用户账目中显式释放仍处于预占状态的请求，须冻结目标用户和请求 ID，填写 1–256 字符原因，并记录操作者与原因；仅原子转换预占记录，已结算／释放的请求不再次退额。手动释放后该请求不再向用户扣费，仍在进行的上游费用由平台承担；这不代表上游已取消，恢复也不能将已释放请求重新提交。
- 普通任务 DTO 只返回本人获准字段，不回传 `providerData`、平台余额、上游源码或凭据；状态、取消、恢复与账本操作均重新检查归属。普通创作入口新增模型能力只放行精确的 `/api/ai/models`、`/api/ai/generate`、`/api/ai/media/models`、`price`、`generate`、`tasks/status`、`tasks/cancel` 和 `/api/multiTenant/user/balance`，不放宽其他管理或执行入口。

## 供应商维护与原有抽象复用

- 供应商 source／config 保存到 SQL `modelRouting` 配置的 `providerCipher`，AES-GCM purpose 为 `providers`，与 `cloud`、`execution` 用途隔离；供应商、路由、价格和平台云配置共用全局 `revision` CAS，跨页面旧版本返回 `409`，不另设互相覆盖的页面版本。
- 供应商、路由和价格页面保存遇到 `409` 时，保留本地未保存输入并展示可见错误，不自动重新加载覆盖草稿，也不无条件重提旧快照；重新读取需沿现有明确交互进行。
- SQL 尚无供应商配置时只读兼容原主机的文本和媒体供应商；首次保存须明确导入完整集合并保留已有供应商身份，不能只保存新加一项而漏掉旧记录。导入不改写原 `settings` 或供应商文件，不隐式删除记录，也不因读取触发自动迁移。
- 沿用原 `.ts` 供应商抽象和 `apps/server/src/utils/media/provider.ts` 的 AST 解析、VM 加载与已有 SDK。文本源码只作为静态 preset 解析协议、连接配置、规则和模型，实际文本执行继续由既有 SDK 完成；媒体复用 `validateMediaProviderSource`、`replaceMediaProviderModels` 与加载原语，不另造 parser、VM 或平行执行门面。
- 宿主 `providerAdapters.ts` 负责 legacy 读取、规范化、描述和源码检查；gateway 统一供应商的读取／保存及来源分派，不在 HTTP 或 UI 重复解析、迁移和执行供应商。供应商后台维护不等于切换 `sourceMapping.providers` 草稿策略，该来源映射的未接入边界保持。
- 保存供应商仅拒绝本次把原本有效的启用路由绑定改为失效；原先已失效的旧绑定不能阻止编辑其他供应商。原有供应商身份保留、配置校验与全局 revision CAS 仍须执行，不为绕过旧故障而删除记录或改派历史任务。
- 供应商表单与模型编辑复用 `@toonflow/provider-web`，网络、全局状态和 SQL 保存由宿主注入／接入，保证认证前后台不因导入表单而加载原有全局设置或业务副作用。源码专属业务文案和供应商实现保持原值，宿主管理操作和校验文案继续多语言。

## 数据源与 ORM

- `provider` 仅允许 `sqlite` 或 `mysql`。SQLite 是默认数据源；MySQL 8.0 是必须支持的集中式数据源，可部署在本地、企业服务器或云端托管数据库。
- SQLite 默认使用 `data/multiTenant/multiTenant.sqlite`，数据库及驱动生成的配套文件由 ORM／数据库驱动管理，不能当普通 JSON 快照读写或覆盖。
- MySQL 的连接地址、端口、数据库名、账号、凭据及必要 TLS 配置由同一数据源配置入口管理；不要把连接信息混入用户偏好或租户可读取的设置。凭据不得回传普通客户端或输出到日志。
- 数据源配置使用现有 Zod 校验；配置文件读写复用 `@toonflow/file`，完整覆盖使用 `writeAtomic`，遵守现有文件权限约定。数据库驱动的内部持久化不重写到文件原语中。
- 数据源和连接生命周期由 `packages/multiTenant/db` 统一管理，宿主通过公开导出接入并由 `utils.ts` 暴露必要能力；禁止每个请求重复初始化连接，也禁止按请求切换全局 `conf`、数据源配置或 `TOONFLOW_DATA_DIR`。
- 业务接口不直接依赖 `bun:sqlite`、`mysql2` 或散落的方言 SQL。必须使用的方言差异集中在数据访问与迁移实现中；ORM 不保证 SQLite 与 MySQL 的字段类型、约束和迁移语法完全相同。
- 数据源切换必须通过显式配置与迁移流程完成，包含备份、数据转换和核验；修改连接配置不等于完成数据迁移。连接或迁移失败时禁止静默回退到新的 SQLite、空数据库或独立模式。
- SQLite 仅用于单实例部署，不将其数据库文件放在共享网络目录供多个服务实例并发访问。多实例部署使用集中式 MySQL；各实例必须连接同一业务数据源并使用兼容的结构版本。

## 数据与设置归属

- 用户、租户、成员关系、权限、设备授权归属、项目登记、分域设置，以及需要跨实例协调的任务归属和可恢复状态由数据库持久化。
- 配置按主机／平台、租户、用户分域。共享供应商凭据、网络、更新、插件安装与服务端执行能力属于平台管理范围；租户策略属于租户；主题、语言、快捷键等属于用户。与租户相关的用户偏好同时带上租户归属。
- `data/settings.json` 继续承担原有独立模式和宿主启动配置职责；多租户业务设置不再通过全局 `settings.stores` 或整份宿主设置快照共同保存。
- 每次读取或保存只能访问已授权范围内的记录，不能让普通用户提交整棵用户、租户或平台设置覆盖其他主体的数据。当前项目和最近打开列表属于界面状态，不是权限依据。
- 画布、素材和对话的现有格式按实际开发阶段兼容，不因引入 ORM 就全量改写。大文件使用文件存储或对象存储，不默认写入数据库 BLOB。
- 旧全局素材、偏好及个人记忆默认归原使用者所在的默认租户／用户；公共共享必须明确授权，不把旧数据默认开放给所有租户。

## 身份与项目授权

- 请求身份由服务端认证生成，包含用户、所选租户及其权限。客户端传来的 `tenantId`、`userId`、目录或对象 ID 仅用于选择目标，必须验证当前身份有权访问。
- 查询、写入、关联查询、批量操作、下载、预览、事件流、任务控制和后台恢复均须校验租户归属；不可只保护普通 JSON 接口，也不可将 UUID 难以猜测当成授权。
- ORM 入口统一执行租户边界，数据库唯一约束、关联约束和索引必须考虑租户范围，避免不同租户的同名记录冲突或跨租户关联。
- 多租户项目使用稳定的 `projectId`，登记所属租户及实际存储位置；对外使用 `projectId` 与项目相对路径。绝对磁盘目录不能作为身份或授权凭据。
- 在现有工作区授权与文件入口中完成多租户适配，前端继续复用 `useWorkspaceFiles`，保留独立模式的目录调用兼容，不让组件重复拼接文件接口。
- 本地项目登记使用规范化真实路径；不同租户的项目根目录不得相同或父子重叠。继续保留目录边界、符号链接、文件冲突和工作区根保护。
- 平台管理员统一管理插件、供应商脚本和外部 MCP，并限制租户可调用的执行能力。允许租户运行不可信服务端代码前，必须具备相应的系统账户、容器等执行隔离，不能把 ORM 或普通子进程当成沙箱。
- 设备的连接、配对与传输授权须关联到用户及租户；当前多租户阶段统一通过 `10888` 创作，旧互联只保留独立模式恢复能力。旧设备令牌不得自动成为创作会话、云端账号或平台管理员凭据；未来云端设备接管仍需账号认领与重新授权。

## 并发、事务与多实例

- 设置和可并发编辑的项目快照使用 `revision` 或等价版本标识。保存携带预期版本，数据库通过条件更新原子完成版本比较、内容更新和版本递增；冲突返回 HTTP `409` 并保留客户端修改。
- 可以继续完整覆盖当前范围的设置，但不能用旧完整快照无条件重试。前端队列、服务端进程内队列和原子文件写入都不能替代跨客户端版本校验。
- 事务只包含必要的短数据库操作，统一加锁顺序，不持事务等待 AI、网络、用户输入或长时间文件处理。死锁重试必须有界且仅重试可安全重复的数据库操作，不重复发起供应商扣费或生成任务。
- 本地文件继续复用现有路径锁和原子写入；锁仅在实际文件操作期间持有，异常通过 `finally` 释放。底层文件许可不可重入，不在相同路径的 `withFileAccess` 回调中再次调用受管文件 I/O。
- 进程内 Map、Set、文件锁、页面保存队列和粘性会话不作为集群一致性的保证。任务调度、执行租约、幂等标识和取消控制需要使用共享且可恢复的状态。
- 多实例运行时，持久项目文件必须由各实例可访问的存储承载；Worker 本地临时目录不能成为唯一数据源。对象存储适配留在所属业务模块，不混入 `@toonflow/file` 的本地原语。
- 数据库事务不能同时原子提交 OSS／磁盘文件；涉及两者时明确提交顺序、版本关联和可恢复状态，失败不得以自动清理为由删除线上对象或记录。
- 会话、任务、MCP 控制、页面连接和事件必须带归属；跨实例传递事件时验证归属及实际连接持有者。权限或设备授权撤销后，已有连接与任务控制也需失效或重新校验。

## 旧数据与迁移

- 开启时由原使用者承接默认租户，平台管理员权限单独授予。已知旧项目默认登记到默认租户，其他租户初始无权访问；未登记目录由管理员明确导入，不自动扫描整个磁盘并开放。
- 本地旧项目优先原地登记，保留画布、素材和对话格式。其他设备连接服务不代表其本地项目已经上传；云端导入必须明确选择项目与目标租户，并保留源数据。
- 项目转交、存储迁移或数据源切换前，先禁止新的相关操作，等待已有保存和任务结束，再提交归属或存储变更；不要持有文件锁等待这些任务。
- 迁移必须可记录进度、避免重复导入，并在核验完成后切换数据源。多实例不得同时竞争执行结构迁移；迁移使用独立发布步骤或受协调的单执行入口，不隐式绑定构建、安装依赖或普通业务请求。
- 未经用户针对具体操作明确确认，禁止线上 `DELETE`、`TRUNCATE`、`DROP`、软删除、级联删除及 OSS 对象／版本删除；ORM 的同步、重置、迁移、回滚和清理能力同样受根规范限制。

## 验证与开发阶段

- 当前发布版本保留创作 Web 设置中的多租户“正在开发”屏障，完整配置面板代码保留但不从该入口加载；只有用户明确要求重新开放时才恢复入口，不以继续开发其他能力为由自动解除。
- 只实现用户当前明确要求的阶段；编写本规范不代表同时实现登录、租户管理、数据库初始化、迁移或云端基础设施。
- 按改动执行已有类型检查、构建及必要手动验证；数据库和配置验证使用隔离的临时数据目录与数据源，不连接或覆盖真实用户配置，不新增测试／自检文件及入口。
- SQLite 与 MySQL 的支持情况分别如实报告；仅验证其中一种时，不宣称另一种已经可用。静态检查或构建通过不能代替租户隔离、并发和迁移行为的实际验证。
