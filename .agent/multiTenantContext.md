# 多租户需求共识与交接说明

本文件沉淀 2026-11-03 本次对话的核心，供其他对话接手。开发规则见 [multiTenant.md](multiTenant.md)，根目录 `AGENTS.md` 要求同时阅读这两份文件。

用户后续明确指令优先；更新本文件时保留未被撤销的目标，不把某次局部任务当成替换整个目标。代码现状以接手时实际读取的仓库为准，不能把设计说明当作已经实现的功能。

## 主旨

在现有 Toonflow 基础上增加真正的多租户能力：不同租户的项目、业务数据、设置与执行权限相互隔离，同时兼容既有独立运行方式和旧项目。

产品面向未来商业部署，可运行在个人电脑、企业服务器或云端，并具备向多实例、负载均衡和独立任务执行进程演进的边界。它不是只给局域网设备共享某台电脑后端的联机功能。

“主机”描述服务端角色，不固定指某台桌面电脑；“租户”是数据与权限范围；“用户”是登录身份；“设备”是接入工具。设备互联、数据库连接和租户归属是不同概念。

## 用户已明确的要求

当前发布边界：用户要求本次版本暂不开放尚未完成的多租户功能。创作 Web 设置中的“多租户能力”入口已恢复原“正在开发”静态屏障（`developmentNotice.vue`），不加载配置／启停面板；已实现代码保留。后续只有用户明确要求恢复开发入口时才重新接入，不能因其他多租户任务顺手解除屏障。

本轮只恢复设置入口的原静态页面及既有文案来源，不改后端、运行开关或已有数据；Web 类型检查与构建通过，构建保留已有的大 chunk／configLoader 提示。

| 事项 | 必须保留的要求 |
| --- | --- |
| 商业化方向 | 设计不能局限于本地主机和局域网，需考虑云端数据库、分布式和负载均衡。 |
| ORM | 必须使用 ORM，集中管理关系数据访问与迁移，不将业务代码绑定到某个数据库驱动。 |
| 数据库 | 必须支持 MySQL 8.0；用户后续明确默认使用 SQLite，两项要求同时保留。 |
| 运行数据 | 开启多租户后，在实际 `data/` 下创建 `multiTenant/`，保存基础数据源配置和默认 SQLite 数据库。 |
| 代码位置 | `packages/multiTenant` 是分组目录而不是总包；`db`、`adminWeb` 等各自是独立工作区包，拥有自己的依赖与公开导出。 |
| 复用边界 | 用户已为多租户准备 `apps/server/src/utils/channel` 与 `packages/file` 抽象，后续优先复用，避免重造。 |
| 交接要求 | 不只记录编码规则，还要保留本次需求主旨，避免其他对话接手后改变方向。 |
| 当前开发阶段 | 开启多租户后主窗口直接显示超管后台，保持到退出；原创作 Web 从 `10888` 访问，普通账号通过 SQL 注册、登录后进入现有创作界面。最新决定覆盖此前“保留主创作窗口、另开后台窗口”的方案。 |
| 开关与入口屏蔽 | 开关写入 `settings.json`；开启后隐藏第三方模型模块和整个开发者选项页面，关闭后恢复，不能删除已有配置。 |
| 主机本人创作 | 从原生后台打开 `10888` 创作 Web，以本次启动的秘密凭据证明主机身份，再由超管访问旧项目；手工访问端口的普通浏览器不能因位于本机就自动成为超管。 |
| 后台导航与页面 | 后台使用左侧栏与 Vue Router，提供总览、配置及本轮明确要求的用户管理页面；认证、启停和创作入口边界保持，不增加虚构统计、组织租户 CRUD 或订阅收费后端。 |
| 普通账号管理 | 真实 SQL 列表、搜索分页、新增、启用／禁用、重置密码；只管理普通账号，不删除、不改变超管角色。禁用账号仍列出；重置、禁用与启用均通过 `authVersion` 使旧会话失效，历史时间 `0` 视为未知。 |
| 创作 Web 注册开关 | 后台配置页提供“允许注册”，SQL 平台策略 `registrationEnabled` 默认 `true`，旧数据同样默认允许。仅超管保存；关闭隐藏公开注册入口且服务端注册返回 `403`，已有登录与后台新增账号不受影响，不删除数据。 |
| 业务数据源映射 | 先前阶段已做固定四项业务来源草稿与 SQL CAS 保存；最新明确模型通过独立显式路由实际处理，供应商来源、插件及社区三项仍为草稿。`sourceMapping` 不是数据库连接设置，其草稿快照仍为 `applied: false`。 |
| 模型别名与实际路由 | 创作 Web 请求对外别名（如 `qwen8`），后端可将其映射到实际 `gpt6` 或 Toonflow 云来源，并支持编辑改绑。`publicId`、永久 `route.id`、`upstreamModelId` 三分；目录单条 `modelId=publicId` 加 `routeId` 迁移旧 UUID，历史执行快照不受改绑影响。 |
| 后台结构与供应商维护 | “模型服务”分供应商管理／模型路由／价格配置，“平台设置”分系统配置／数据源映射；平台专用云凭据移至供应商页。供应商 source／config 在 SQL 加密保存，共用路由全局版本；复用原 AST／VM／SDK 和共享纯表单，不重造解析或执行层。 |
| 用户余额扣费 | 本阶段明确实现 SQL 钱包、管理员给单用户增加余额、幂等预占／结算／释放与最近账目，覆盖此前暂未授权计费的限制。普通账号按 CNY／USD 自有钱包扣费，超管本人不扣内部余额；不包括在线支付、套餐、负值充值或删账。 |
| 统一模型网关 | 最新明确不能只分包而让路由、来源与计费散在入口；独立 `gateway` 统一编排，单向依赖 `models`／`billing`。宿主只注入来源与协议能力，文本、媒体复用同一预占和 outcome 完成契约，不再复制平行门面或钱包分支。 |
| 四类模型全链路统一 | 文本、图片、视频、音频共用 nodeAi／modelCatalog 与 gateway，稳定 routeId 在真实 HTTP 前解析当前别名；SDK 内部 turn 和三类媒体工具也沿统一账务，不开放普通 Agent、调试或个人模型搜索旁路。 |
| 主机与租户创作入口 | 按架构图强化一次 createApp／同一 Bun 业务后端：私有端口负责控制与 adminWeb，主机本人和租户创作都走 `10888` Web 会话。私有创作 API、公开管理／旧 providers 旁路均拒绝；主机创作 settings 只读写白名单范围，旧互联配置保留供独立模式恢复。 |

数据库选型的最终口径是“默认 SQLite，同时支持 MySQL 8.0”。此前讨论过只用文件或只用 MySQL 的方案，均不能覆盖用户最后明确的默认值；SQLite 默认也不代表商业集群共享一个 SQLite 文件。

## 本轮采用的设计基线

以下来自此前代码分析与方案讨论，用于解释开发规则的来由；它们不是已完成的功能，也不表示用户已确认全部界面和实现细节。需要改变这些基线时应说明与既有目标的关系，不能在局部实现中悄悄替换。

| 原始问题 | 当前方案基线 |
| --- | --- |
| 服务端成为主机后，原 Web 怎么办？ | 保留 Web；Web 只是入口，原使用者可以属于默认租户，平台管理权限与租户创作权限分开。 |
| 旧项目怎么分配？ | 已知旧项目优先归默认租户，通过服务端项目登记建立稳定 `projectId` 与归属；本地项目优先原地登记，由管理员明确转交或导入。 |
| 设备互联是否保留？ | 保留原配置与独立模式能力；最新入口分工要求多租户主机与租户统一从 `10888` 创作，旧互联不能成为旁路。未来设备接入仍须用户／租户授权，连接主机不代表上传项目或获得其他主体权限。 |
| 旧数据怎么兼容？ | 优先兼容画布 JSON、素材路径和对话历史；全局素材、个人记忆、设置和任务记录也要处理归属，不能只给项目列表增加字段。 |
| 文件夹会不会死锁？ | 文件夹本身不是问题。现有锁只协调单进程文件操作；多客户端旧快照覆盖和跨实例任务协调需要单独解决。 |
| 用户设置怎么避免竞写？ | 主机／平台、租户、用户分域保存，使用版本条件更新防止旧快照覆盖；仅排队或改用 SQL 都不能自动解决丢失更新。 |

- SQL 优先承载身份、归属、权限、设置及需要共享的运行状态，不因引入数据库就把所有素材和历史项目转换为数据库内容。
- 独立运行模式继续兼容；多租户项目逐步使用 `projectId` 与相对路径，实际磁盘路径或对象存储位置由服务端解析和授权。
- 默认 SQLite 对应单实例使用，集中式 MySQL 对应后续多实例部署。数据库切换需要显式迁移、备份与核验，不能只改连接地址或失败后静默创建空库。
- 云端多实例不能依赖某个实例的本地目录、内存 Map、页面保存队列或粘性会话保存唯一业务状态。共享存储、队列和事件能力按实际阶段接入，不要求本轮一次上线全部基础设施。
- 继续复用现有前端 `useWorkspaceFiles` 入口、服务端路径边界与 `@toonflow/file` 原语；租户授权和业务存储适配留在相应业务模块。

## 代码现状与容易误读的点

以下是本次静态阅读的发现，接手时需要重新核对相关改动：

- `apps/web/src/stores/workspace.ts` 的项目当前仍以绝对目录识别。项目列表通过 `apps/web/src/stores/settings.ts` 的 `settingsStorage` 写入服务端设置；普通账号的数据写入自己的 SQL 设置记录，超管和独立模式保留原设置，不能把它当作仅存在浏览器 localStorage 的数据。
- `apps/server/src/utils/workspace/index.ts` 已增加普通账号根目录边界，超管可以访问旧项目。本阶段是账号工作区隔离，尚不能替代后续“用户 → 组织租户 → 项目登记”的完整归属模型。
- 全局素材位于数据目录的 `assets/`；媒体任务位于 `mediaTasks/` 下、按项目目录哈希关联。项目内容并不只存在项目文件夹，随意搬目录会影响关联。
- 普通账号设置已使用 SQL `revision` 条件更新，跨页面旧快照保存冲突返回 `409`；独立模式设置保留原完整快照协议，多租户主机创作只完整替换获准白名单范围并沿用进程内队列，没有新增主机 CAS，不能宣称所有配置和项目快照均有跨客户端 CAS。
- `apps/server/src/utils/channel` 已有 `Channel` 契约和部署级渠道选择，提供账号、钱包、市场、模型与供应商来源等业务能力。它不是 SQLite／MySQL 的持久化连接配置；现有请求适配仍需调整按用户／租户解析凭据的方式。
- `packages/file` 已提供原子提交和进程内路径队列，后续应复用；这不等于已实现跨租户授权、跨进程锁或对象存储事务。
- Agent、临时会话、MCP 页面连接等存在进程内状态，后续涉及多实例时需要逐条处理归属、恢复和事件路由，不能只增加数据库表就宣称支持负载均衡。

## 尚未定案的实现细节

- 首阶段实现已采用 Drizzle ORM，默认 SQLite，MySQL 8.0 使用 mysql2 适配；这是本轮实现选型，不是用户指定了具体 ORM 品牌。
- 当前已实现超管配置和控制、普通账号注册登录、账号设置与工作区文件边界；总览、配置、普通账号管理以及最新模型路由与用户余额扣费均已获明确授权，不能再用此前阶段的“未授权用户 CRUD／计费”限制阻断。组织租户、成员角色、项目共享、在线支付和套餐等业务仍未指定，不自行加入示例数据或其他经营流程。
- Redis、任务队列、OSS 服务商、云部署平台及具体调度方案尚未指定；应保持可扩展边界，不提前强制加入全部依赖。
- 画布和对话的最终存储介质、实时协作方式、项目共享粒度及数据迁移工具尚未完整定案，按实际需求推进，不默认开展全量重构。
- 商业化目标不等于本阶段授权开发订阅套餐、收费体系或其他新业务；已有渠道能力仅在当前需求涉及时复用。
- 用户最新明确模型路由、上游成本、用户售价、平台专用云凭据与余额扣费在本阶段独立接入实际请求，覆盖此前仅草稿、暂不计费的限制。供应商来源、插件与社区映射仍只配置保存；云端个人账号映射未授权，不复用全局个人云令牌，也不加入空字段或假数据。
- 用户后续进一步更正模型层的核心目标是“对外别名 → 多租户后端路由 → 实际模型／云来源”，不是只把上游模型列给创作端选择。别名、供应商维护、模型路由和价格配置均已明确授权；维护后端供应商配置与尚未切换的 `sourceMapping.providers` 草稿是两件事，不能再用旧阶段限制阻断维护页面。

## 本次交接状态与接手方式

- 已完成代码分析、方案讨论，以及 `AGENTS.md` 的引用和 `.agent/` 中的多租户规范与交接文档；现有独立包为 `db`、`auth`、`adminWeb`、`userWeb`、`sourceMapping`、`models`、`billing` 与最新统一编排领域 `gateway`。原父目录总包已拆除，gateway 也不是父总包，宿主按各包公开导出接入。
- 启停标记为 `settings.multiTenantEnabled`，普通设置保存不能修改它。密码及数据库会话凭据保存哈希；管理页面使用 HttpOnly Cookie，管理会话绑定当前服务进程，退出 Toonflow 后失效，不在 URL 或浏览器持久缓存保存管理令牌。
- 用户后续明确：已配置的设置页保留开关与后台入口，覆盖此前“仅跳板”的默认方案；开启时隐藏整个开发者选项页面，而非只隐藏其中部分工具。
- 最新窗口决定：启动时已开启或进程中首次开启多租户后，桌面主窗口改为超管后台。主机模式在本进程内保持，关闭开关只停止创作网关，退出后以关闭状态重启才恢复独立创作；重载或再次激活不能回创作主页。此前新增的独立后台窗口已取消，新的普通 Web 窗口用于打开 `10888` 创作入口。
- 主窗口通过原生 preload 的 `/api/multiTenant/hostSession` 兑换主机 Cookie；创作窗口通过 `/api/multiTenant/user/host` 兑换超管创作会话。两者验证本次启动生成的随机 secret，前端等待 `window.toonflowHostReady`；secret 不进入 URL 或磁盘，公开入口不凭本机地址、Host 或主机管理 Cookie 自动授予超管。手工访问 `10888` 的浏览器走登录流程。
- 原生创作窗口首次成功兑换后只保留非敏感的窗口会话标记，重载不再次兑换；用户显式退出优先，退出后返回登录页，关闭后新开窗口仍可默认超管。sessionStorage 受限时以窗口名称作为标记回退，不保存任何秘密凭据；主窗口重载仍按本次启动的主机身份恢复后台。
- `10888` 是同一个应用的受保护创作网关，由 server 公共运行时统一管理，不是另起一套后端。`createApp` 不监听，桌面连接与独立 server 启动入口各自显式启动运行时；普通公网请求不能访问主机管理接口。
- 普通用户以 SQL 账号注册、登录，成功后进入旧创作 Web，设置菜单提供当前账号和退出入口；超管通过同一创作入口访问旧设置和旧项目，不自动迁移或清理源数据。旧仅密码认证记录继续兼容为账号 `admin`，保留密码，不重置数据库。
- 普通账号设置保存在其 SQL 记录，限制可保存字段并通过 `revision` CAS 防止旧快照覆盖；普通账号工作区根为实际 `data/multiTenant/workspaces/<userId>/`，不开放超管旧项目、兄弟账号目录或符号链接越界。
- 普通账号保留已隔离的设置、工作区及明确允许的只读接口；最新阶段新增精确方法／路径的平台模型目录、文本生成、媒体目录／报价／生成、本人任务状态／取消和本人余额。serverAgent、MCP、全局素材、全局供应商管理及平台余额 SSE 等仍返回 `403`，不能因模型已接入就宣称组织租户、全部创作能力或项目登记迁移已经完成。
- 独立包分别为 `@toonflow/multi-tenant-db`、`@toonflow/multi-tenant-auth`、`@toonflow/multi-tenant-admin-web`、`@toonflow/multi-tenant-user-web`、`@toonflow/multi-tenant-source-mapping`、`@toonflow/multi-tenant-models`、`@toonflow/multi-tenant-billing` 与 `@toonflow/multi-tenant-gateway`；根工作区登记 `packages/multiTenant/*`，宿主按实际依赖导入相应包，父目录不保留总包入口。
