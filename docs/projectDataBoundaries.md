# Toonflow 数据边界

[返回项目圣经](./projectBible.md)

## 数据目录

| 数据 | 默认位置 | 规则 |
| --- | --- | --- |
| 应用设置 | `<dataDirectory>/settings.json` | `conf` 单例，模式 `0600`，完整覆盖保存 |
| 节点 | `<dataDirectory>/nodes` | 安装/启用/卸载由 Server 管理 |
| 工具 | `<dataDirectory>/tools` | 开发同步可覆盖同名副本 |
| 扩展 | `<dataDirectory>/ext` | 由扩展初始化器装载 |
| 提供方 | `<dataDirectory>/providers` | 内置提供方按源码修订同步，独立提供方保留 |
| 技能 | `<dataDirectory>/skills` | 默认首次补齐，用户修改保留 |
| 团队 | `<dataDirectory>/agents` | 只有配置启用 `agentsRoot` 时随宿主装载 |
| 工作区 | 用户选择的绝对目录 | 业务文件由工作区 API 访问，不能越界 |
| 构建产物 | `build/` | 可删除重建，不作为用户数据来源 |
| 日志 | `logs/` 或部署指定目录 | 不提交，不保存密钥 |

开发环境默认使用仓库根目录 `data/`；生产环境应使用安装目录同级的 `data/`，避免写入可更新的程序资源目录。`data/` 必须保持 Git 忽略。

## 工作区文件

前端只通过 `useWorkspaceFiles` 读写工作区。`directory` 是绝对路径，`path`/`target` 是工作区内相对路径。目录未选择时操作必须报错；显式传入目录时不回退到当前 Pinia 项目。

跨 `await` 的多步操作、保存队列和防抖操作开始时先取得目录快照，再创建固定目录实例，防止用户切换项目后读写到另一个目录。`readJson<T>` 只负责解析，不校验业务标记或结构。

覆盖画布、JSON、配置快照时显式使用原子写入；新建且不能覆盖时使用独占写入。写入、改名、删除或创建目录失败必须原样抛出，调用方负责显示错误或回滚。

## 设置与项目列表

- Server 设置接口接收 `{ settings: { ... } }`，保存是完整覆盖；读取未保存设置返回 `{}`。
- `u.conf` 是唯一配置入口，不在路由或请求中重新创建实例。
- Web 项目列表由 Pinia 持久化，移除列表项不删除工作区目录。
- 语言设置影响请求语言回退和响应消息；技术值、路径和代码内容仍保持可解析格式。

## 插件安装安全边界

- 安装地址仅允许 HTTP/HTTPS；包类型、大小、文件名和压缩格式由对应路由校验。
- 节点、工具、技能、提供方和扩展的安装目录互不混用。
- 同名资源的更新/覆盖规则由资源类型决定；不要在调用方复制一套版本比较或路径校验。
- 真实 API Key、令牌、私有工作区、媒体素材和本机配置不能提交或上传到 Issue/PR。

## 部署边界

Server 进程只支持单进程内的配置和文件占用协调，不支持多个进程并发写同一工作区。部署时为每个实例提供独立可写数据目录；容器挂载持久化 `data/`，并保证运行用户有权限写入。
