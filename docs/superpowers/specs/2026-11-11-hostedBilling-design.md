# 托管系统设置、用户钱包与上游账单对账

用户已选择：实际扣费 = 可核对的上游账单金额 × 倍率，不用 token 单价估算费用。

## 页面与权限

- 账户保留个人信息、密码、任务、临时结果，新增余额与扣费明细。
- 管理员独立「用户管理」页保留创建、启停、存储上限与密码重置，并增加余额增减、个人倍率和调整流水。
- 管理员独立「系统设置」页配置计费开关、默认倍率，显示上游连接及金额换算信息，支持重新核对账单。
- 普通用户仅能查看自己的钱包、流水和任务。余额、倍率及结算只能由服务端计算。

## 费用来源

- 首先接入现有 OpenFox/New API 协议：生成响应 `X-Oneapi-Request-Id` 对应 `/api/log/token` 中 `request_id`，消费日志类型为 2。
- `/api/status` 的 `quota_per_unit` 为每美元额度，人民币金额为 quota / quota_per_unit × usd_exchange_rate。2026-11-11 公开接口返回 500000 和 7.3；代码读取服务端真实值，不硬编码费率。
- 每笔调用保存 Request ID、凭据摘要、换算快照、计费开关和倍率。不得保存请求正文、提示词或 API Key，不使用用户日志中随分页改变的显示 ID 对账。
- 同一账单唯一结算；无 Request ID、没有匹配日志、查询失败或不支持的上游均显示待核对，绝不记成零费用。旧任务没有对应请求证据，不追溯自动扣款。
- 一项 Agent 任务的多轮模型、工具内媒体调用分别记录，按任务汇总；失败和取消不代表上游未扣费。
- 同步文本/图片匹配唯一消费日志结算；异步视频仅在相同 `task_id` 的日志中有唯一明确的 `actual_quota` 最终快照时结算。缺少该快照（包括无差额未出结算日志、退款尚未明确）的任务保留待核对，防止把预扣误作最终账单。

## 钱包与数据

- SQLite 追加钱包、调整流水、账单引用与结算表，不修改已有账户和任务历史。
- 金额采用百万分之一人民币的安全整数，倍率采用万分之一整数。每笔扣费和流水在一个事务中提交，唯一键防止重复扣款。
- 初始余额 0；计费默认关闭以兼容已有用户。管理员开启后新任务按启动时快照计费，关闭时不抹去已发生的应付账单。
- 管理员增减余额要求当前密码、操作 UUID 和备注；余额不能由前端直接覆盖，重复操作 UUID 不重复记账。
- 余额非正时拒绝新的付费请求。实际账单只能事后取得，单笔最终费用可能使余额为负；不宣称具有预付费硬上限，结算后阻止继续调用。
- 未取得的账单保留待核对，管理员可重试；不通过共享 Key 的余额差推断单个用户费用。
- 任务结束时核对，随后每分钟重试；每批至多 500 条，按最近核对时间轮换，防止无法匹配的旧记录阻挡新账单。

## 同一会话已有修复

媒体供应商密钥眼睛无法显示的原因是设置接口返回了固定掩码。管理员打开已有媒体供应商编辑时，使用带 `mediaProviderId` 的同一只读设置接口只取得该供应商真实配置；默认接口仍返回掩码，普通用户请求该参数返回 403。数据不加入全局前端设置存储，响应使用 no-store。

## 验证与边界

遵守 AGENTS.md，不增加任何测试模块、临时测试脚本或依赖。运行现有前后端类型检查、构建及路由生成，进行必要手动验证。不上线、不发起付费模型调用、不修改真实用户余额；真实上游的扣费闭环须在已有真实账单或获准调用后验证。
