### FilmFraylo वापरून AI शॉर्ट ड्रामा आणि कॉमिक ड्रामा कसे बनवायचे

1. **पटकथा आणि स्टोरीबोर्ड लिहा**: मजकूर नोडमध्ये कथा, पात्र सेटिंग्ज आणि शॉटचे वर्णन मांडा; भाषा मॉडेलच्या सहाय्याने निर्मिती करा आणि नंतर आढावा घेऊन सुधारणा करा.
2. **पात्रे आणि दृश्य अॅसेट्स तयार करा**: संदर्भ प्रतिमा इंपोर्ट करा किंवा प्रतिमा जनरेशन नोडद्वारे पात्रे, दृश्ये आणि स्टोरीबोर्ड प्रतिमा तयार करा.
3. **व्हिडिओ शॉट तयार करा**: मजकूर आणि प्रतिमा संदर्भ जोडा, व्हिडिओ मॉडेल आणि जनरेशन मोड निवडा आणि प्रत्येक शॉटनुसार व्हिडिओ क्लिप तयार करा.
4. **प्रीव्ह्यू, आयोजन आणि डाउनलोड**: अमर्याद कॅनव्हासवर प्रतिमा व व्हिडिओ क्लिप्स पहा आणि व्यवस्थित करा; अॅसेट्स डाउनलोड करून निर्मितीच्या गरजेनुसार पुढे वापरा.

समर्थित संदर्भ अॅसेट्स, व्हिडिओ कालावधी, रिझोल्यूशन आणि ऑडिओ क्षमता निवडलेल्या मॉडेलवर अवलंबून असतात.

### सामान्य प्रश्न

**FilmFraylo AI शॉर्ट ड्रामा आणि कॉमिक ड्रामा निर्मितीच्या कोणकोणत्या टप्प्यांसाठी वापरता येते?**

FilmFraylo मजकूर, प्रतिमा आणि व्हिडिओ जनरेशन नोड्स देते; हे नोड्स पटकथा व स्टोरीबोर्ड निर्मिती, पात्रे व दृश्य अॅसेट्स तयार करणे, व्हिडिओ शॉट जनरेशन, तसेच अॅसेट्सचे प्रीव्ह्यू व आयोजन यासाठी वापरता येतात. निर्मात्यांना सामग्रीचा आढावा घेऊन ती समायोजित करावी लागते; प्रत्यक्ष जनरेशन क्षमता निवडलेल्या मॉडेलवर अवलंबून असते.

**FilmFraylo मोफत आहे का? मॉडेल वापरासाठी पैसे द्यावे लागतात का?**

FilmFraylo MIT ओपन सोर्स परवान्याखाली आहे आणि स्वतः डिप्लॉय करता येते. मॉडेल कॉलचे बिल अधिकृत मॉडेल प्लॅटफॉर्म वापरानुसार आकारते; त्यासाठी आधी अॅपमध्ये API Key कॉन्फिगर करणे आवश्यक आहे. नमुना कलाकृतींमधील निर्मिती खर्च फक्त त्या उदाहरणापुरता आहे, तो निश्चित दर नाही.

**माझे स्वतःचे मॉडेल जोडता येते का?**

सध्याच्या आवृत्तीत अधिकृत मॉडेल प्लॅटफॉर्म अंगभूत आहे आणि मॉडेल्स अधिकृत FilmFraylo मॉडेल प्लॅटफॉर्मकडून मिळतात; सध्या तृतीय-पक्ष मॉडेल्स किंवा लोकल ComfyUI वर्कफ्लो जोडण्याला समर्थन नाही.

<details>
<summary><strong>macOS इंस्टॉल किंवा उघडता येत नसेल तर काय करावे</strong></summary>

**1. "गोपनीयता आणि सुरक्षितता" मध्ये FilmFraylo ला परवानगी द्या**

```bash
sudo xattr -rd com.apple.quarantine /Applications/FilmFraylo.app
```

**3. शेवटचा उपाय: कोणत्याही स्रोतातील अॅप्सना तात्पुरती परवानगी द्या**

पहिल्या दोन पद्धती निष्फळ ठरल्या आणि अॅपचा स्रोत विश्वसनीय असल्याची खात्री असेल, तर टर्मिनलमध्ये हे चालवा:

```bash
sudo spctl --master-disable
```

नंतर "सिस्टम सेटिंग्ज → गोपनीयता आणि सुरक्षितता" उघडा आणि "सुरक्षितता" विभागातील "येथून डाउनलोड केलेल्या अॅप्सना परवानगी द्या" या पर्यायात "कोणत्याही स्रोतातून" निवडा (सिस्टमने हा पर्याय दिल्यास) आणि सूचनेनुसार पुष्टी करा. macOS च्या वेगवेगळ्या आवृत्त्यांमध्ये पर्याय व कमांड समर्थन वेगळे असू शकते.

या क्रियेमुळे सर्व अ‍ॅप्सवरील सुरक्षा निर्बंध शिथिल होतात. काम पूर्ण झाल्यावर परवानगीचा स्रोत पुन्हा "App Store आणि मान्यताप्राप्त डेव्हलपर" वर आणण्याची शिफारस केली जाते.

</details>

### 3.2 Docker इंस्टॉलेशन

आधी Git, [Docker Engine](https://docs.docker.com/engine/install/) आणि Docker Compose इंस्टॉल करा; Windows / macOS वर Docker Desktop चा Linux कंटेनर मोड वापरता येतो. रेपॉझिटरीत [Dockerfile](./Dockerfile), [Compose कॉन्फिगरेशन](./compose.yaml) आणि [बिल्ड वगळण्याचे नियम](./.dockerignore) दिलेले आहेत; बिल्ड Bun 1.3.14 वर आधारित असून इमेजमध्ये FFmpeg समाविष्ट आहे.

<details>
<summary><strong>Docker इंस्टॉलेशनच्या पायऱ्या उघडा</strong></summary>

सोर्स क्लोन केल्यानंतर रेपॉझिटरीच्या मूळ डिरेक्टरीत हे चालवा:

```sh
git clone https://github.com/zechau/filmfraylo-app.git
cd filmfraylo-app
docker compose up -d --build
```

पहिल्या बिल्डमध्ये डिपेंडन्सीज इंस्टॉल होतात आणि अंगभूत नोड्स, टूल्स, Web व Server कंपाइल होतात. सुरू झाल्यावर `http://127.0.0.1:3000` ला भेट द्या; दूरच्या होस्टसाठी खालील "प्रवेश आणि डेटा स्पष्टीकरण" नुसार SSH टनेलद्वारे प्रवेश करा. पहिल्या सुरुवातीला अंगभूत प्लगइन्स इनिशियलाइज होतात आणि `myProject` वर्किंग डिरेक्टरी मिळते.

कॉन्फिगरेशन, प्लगइन्स आणि प्रोजेक्ट फाइल्स Docker नामित व्हॉल्यूम `filmfrayloData` मध्ये साठवल्या जातात, जो कंटेनरच्या `/app/data/` वर माउंट केलेला असतो. व्हॉल्यूमचे प्रत्यक्ष नाव Compose प्रोजेक्ट प्रीफिक्ससह असते; कंटेनर थांबवल्यास किंवा पुन्हा तयार केल्यास डेटा टिकून राहतो, **कृपया `docker compose down -v` वापरू नका, ती कमांड डेटा व्हॉल्यूम हटवते**.

```sh
docker compose logs -f filmfraylo  # लॉग पहा
docker compose stop                # सेवा थांबवा
docker compose start               # पुन्हा सुरू करा
docker compose down                # कंटेनर हटवा, डेटा व्हॉल्यूम ठेवा
```

प्रोजेक्ट डिरेक्टरी जोडायची असल्यास पृष्ठावरील "सर्व्हर वर्किंग डिरेक्टरी निवडा" डायलॉगमध्ये "नवीन फोल्डर" वर क्लिक करा. डायलॉगमधून फाइल व फोल्डरचे नाव बदलणे, हटवणेही शक्य आहे. सेवा चालू असताना कमांड लाइनमधूनही तयार करता येते:

```sh
docker compose exec filmfraylo mkdir -p /app/data/workspaces/newProject
```

बॅकअप घेण्यापूर्वी सेवा थांबवा, कॉपी पूर्ण झाल्यावर पुन्हा सुरू करा:

```sh
docker compose stop
docker compose cp filmfraylo:/app/data ./filmfrayloBackup
docker compose start
```

</details>

### 3.3 सर्व्हर इंस्टॉलेशन

Linux सर्व्हरवर थेट Web आणि Server चालवण्यासाठी योग्य. खालील उदाहरण Ubuntu / Debian साठी असून प्रोजेक्टने निर्दिष्ट केलेला [Bun 1.3.14](https://bun.sh/docs/installation) वापरतो.

<details>
<summary><strong>सर्व्हर इंस्टॉलेशनच्या पायऱ्या उघडा</strong></summary>

रनटाइम वातावरण इंस्टॉल करा:

```sh
sudo apt-get update
sudo apt-get install -y git curl unzip ffmpeg
curl -fsSL https://bun.com/install | bash -s "bun-v1.3.14"
export PATH="$HOME/.bun/bin:$PATH"
bun --version
```

सोर्स क्लोन करा आणि सुरू करा:

```sh
git clone https://github.com/zechau/filmfraylo-app.git
cd filmfraylo-app
bun install --frozen-lockfile

# अंगभूत नोड्स, टूल्स, Web व Server बिल्ड करा
bun run build:server
mkdir -p data/workspaces/myProject
bun run start:server
```

"सेवा यशस्वीपणे सुरू झाली" असे दिसल्यावर सर्व्हरवरच `http://127.0.0.1:3000` उघडू शकता. वरील कमांड्स फोरग्राउंडमध्ये चालतात, `Ctrl+C` दाबून थांबवा; बूटवेळी स्वयंचलित सुरुवात आणि प्रोसेस व्यवस्थापन हवे असल्यास [Bun चे systemd डिप्लॉयमेंट मार्गदर्शन](https://bun.sh/guides/ecosystem/systemd) पहा — वर्किंग डिरेक्टरी रेपॉझिटरी डिरेक्टरी ठेवा, सुरू करण्याची कमांड Bun चा निरपेक्ष पथ + `run start:server` ठेवा, आणि त्या डिरेक्टरीवर वाचन-लेखन अधिकार असलेल्या वापरकर्त्याने चालवा.

</details>

### 3.4 प्रवेश आणि डेटा स्पष्टीकरण

- सध्याची सेवा निश्चित पोर्ट `3000` वापरते; व्यवसाय पृष्ठे आणि API साठी स्वतंत्र लॉगिन प्रमाणीकरण नाही. सर्व्हर इंस्टॉलेशनमध्ये फायरवॉल किंवा सिक्युरिटी ग्रुपद्वारे पोर्ट `3000` वरील प्रवेश स्रोत मर्यादित करा; पब्लिक नेटवर्कवरून प्रवेशासाठी प्रमाणीकरणासह रिव्हर्स प्रॉक्सी कॉन्फिगर करा.
- वैयक्तिक दूरस्थ वापरासाठी स्वतःच्या संगणकावर `ssh -N -L 3000:127.0.0.1:3000 用户名@服务器地址` चालवा, कनेक्शन टिकवून `http://127.0.0.1:3000` उघडा; सर्व्हरचा `3000` पोर्ट पब्लिक नेटवर्कला उघडण्याची गरज नाही.
- थेट इंस्टॉलमध्ये कॉन्फिगरेशन, प्लगइन्स आणि वर्कस्पेस डिफॉल्टनुसार रेपॉझिटरीच्या `data/` मध्ये साठवले जातात; Docker इंस्टॉलमध्ये मात्र डेटा व्हॉल्यूममधील `/app/data/` मध्ये. स्थलांतरण किंवा बॅकअप घेतेवेळी ते पूर्णपणे जतन करा. पृष्ठ उघडल्यावर सर्व्हर वर्कस्पेसचा `myProject` निवडा; अधिक प्रोजेक्टसाठी संबंधित `workspaces/` खाली सबडिरेक्टरी तयार करा.
- दोन्ही इंस्टॉलेशन पद्धतींमध्ये सिस्टम FFmpeg समाविष्ट आहे. मॉडेल सेवेचा API Key मात्र अजूनही पृष्ठातच कॉन्फिगर करावा लागतो.
