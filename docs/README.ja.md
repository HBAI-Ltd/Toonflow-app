## 2. 🌟 特長

Toonflow はショートドラマ、モーションコミック、ショート動画の制作に向けたオープンソースの AI 制作プラットフォームです。脚本、素材、動画クリップを一つの無限キャンバスにまとめられます。

| 機能 | 説明 |
| --- | --- |
| 🏠 **ローカル環境で運用** | プロジェクトと素材を自分のデバイスやサーバーに保存。デスクトップ、Docker、サーバーへの導入に対応しています。 |
| 🖼️ **無限キャンバス** | 同じキャンバス上で脚本、キャラクター、シーン、動画クリップを整理できます。 |
| 🔌 **MCP** | MCP を通じて外部ツールやサービスに接続できます。 |
| 🧩 **プラグインマーケット** | [プラグインマーケット](https://api.toonflow.net/console/plugIn)からノード、ツール、制作機能を追加できます。 |
| 🤖 **オープンな Agent** | プロンプト、ツール、A2A のオープンな仕組みにより、Agent の動作のカスタマイズと外部連携に対応します。 |
| 🔧 **モデルを自由に接続** | サードパーティーの API に加え、ローカルの ComfyUI や LLM も接続できます。 |

## 4. 🚀 ダウンロードとインストール

### 4.1 デスクトップ版のインストール

| OS | GitHub |
| --- | --- |
| Windows | [リリース](https://github.com/HBAI-Ltd/Toonflow-app/releases) |
| macOS | [リリース](https://github.com/HBAI-Ltd/Toonflow-app/releases) |

Windows のインストーラーは WebView2 を自動で検出し、必要に応じてインストールします。インストール後、起動直後に終了する場合は、[WebView2 ダウンロードページ](https://developer.microsoft.com/microsoft-edge/webview2/)からランタイムを手動でインストールしてください。

macOS（Apple Silicon）では、Toonflow を「アプリケーション」にドラッグして、そのまま開いてください。事前にターミナルでコマンドを実行する必要はありません。システムのセキュリティ警告が表示された場合は、以下の順に対処してください。

<details>
<summary><strong>macOS でインストールできない・開けない場合</strong></summary>

**1.「プライバシーとセキュリティ」で Toonflow の実行を許可する**

「開発元を検証できません」や「Apple では、このアプリに悪質なソフトウェアが含まれていないことを確認できません」と表示された場合は、一度 Toonflow を開こうとしてから、「システム設定 → プライバシーとセキュリティ」を開きます。Toonflow の実行がブロックされた旨の表示を探し、「このまま開く」をクリックして確認してください。詳細は [Apple の公式案内](https://support.apple.com/zh-cn/102445)をご覧ください。

**2. 隔離属性が原因で引き続き開けない場合は、属性の削除を試す**

公式リリースページから入手したアプリであり、「アプリケーション」に配置済みであることを確認したうえで、ターミナルで以下を実行してから開き直してください。アプリ名やインストール先が異なる場合は、パスを変更してください。

```bash
sudo xattr -rd com.apple.quarantine /Applications/toonflow.app
```

**3. 最後の手段：すべての提供元からのアプリを一時的に許可する**

上の 2 つの方法で解決せず、アプリの入手元が信頼できると確認できた場合は、ターミナルで次のコマンドを試せます。

```bash
sudo spctl --master-disable
```

続いて「システム設定 → プライバシーとセキュリティ」を開き、「セキュリティ」の「アプリケーションの実行許可」で「すべてのアプリケーションを許可」を選択し（その選択肢がある場合）、画面の案内に従って確認してください。利用できる設定やコマンドは macOS のバージョンによって異なります。

この操作は、すべてのアプリに対するセキュリティ制限を緩和します。作業後は、許可する入手元を「App Store と確認済みの開発元」に戻すことをおすすめします。

</details>

詳しい操作方法は[ユーザーガイド](https://qcn7xdsqgc4z.feishu.cn/docx/RXFqdgR2Xo0dXZxGfd0cZCGgnwf)をご覧ください。

### 4.2 Docker でのインストール

まず Git、[Docker Engine](https://docs.docker.com/engine/install/)、Docker Compose をインストールしてください。Windows / macOS では Docker Desktop の Linux コンテナモードを利用できます。リポジトリには [Dockerfile](../Dockerfile)、[Compose 設定](../compose.yaml)、[ビルド除外設定](../.dockerignore)が含まれています。Bun 1.3.14 を使用してビルドし、イメージには FFmpeg も含まれます。

<details>
<summary><strong>Docker のインストール手順を開く</strong></summary>

ソースコードをクローンし、リポジトリのルートディレクトリで実行します。

```sh
git clone https://github.com/HBAI-Ltd/Toonflow-app.git
cd Toonflow-app
docker compose up -d --build
```

初回ビルドでは依存パッケージをインストールし、組み込みノード、ツール、Web、Server をコンパイルします。起動後は `http://127.0.0.1:3000` にアクセスしてください。リモートホストの場合は、下の「アクセスとデータについて」を参考に SSH トンネルで接続できます。初回起動時に組み込みプラグインを初期化し、`myProject` 作業ディレクトリを用意します。

設定、プラグイン、プロジェクトファイルは Docker の名前付きボリューム `toonflowData` に保存され、コンテナの `/app/data/` にマウントされます。実際のボリューム名には Compose のプロジェクト名が接頭辞として付きます。コンテナを停止・再作成してもデータは保持されますが、**`docker compose down -v` は使用しないでください。このコマンドはデータボリュームを削除します**。

```sh
docker compose logs -f toonflow  # ログを表示
docker compose stop             # サービスを停止
docker compose start            # 再起動
docker compose down             # コンテナを削除し、データボリュームは保持
```

プロジェクト用ディレクトリを追加するには、画面の「サーバーの作業ディレクトリを選択」ダイアログで「新しいフォルダー」をクリックします。このダイアログでは、ファイルやフォルダーの名前変更・削除もできます。サービスの実行中にコマンドラインで作成することも可能です。

```sh
docker compose exec toonflow mkdir -p /app/data/workspaces/newProject
```

バックアップ時は先にサービスを停止し、コピーが完了してから再起動します。

```sh
docker compose stop
docker compose cp toonflow:/app/data ./toonflowBackup
docker compose start
```

</details>

### 4.3 サーバーへのインストール

Web と Server を Linux サーバー上で直接実行する場合の手順です。以下では Ubuntu / Debian を例に、プロジェクト指定の [Bun 1.3.14](https://bun.sh/docs/installation)を使用します。

<details>
<summary><strong>サーバーへのインストール手順を開く</strong></summary>

実行環境をインストールします。

```sh
sudo apt-get update
sudo apt-get install -y git curl unzip ffmpeg
curl -fsSL https://bun.com/install | bash -s "bun-v1.3.14"
export PATH="$HOME/.bun/bin:$PATH"
bun --version
```

ソースコードをクローンして起動します。

```sh
git clone https://github.com/HBAI-Ltd/Toonflow-app.git
cd Toonflow-app
bun install --frozen-lockfile

# 組み込みノード、ツール、Web、Server をビルド
bun run build:server
mkdir -p data/workspaces/myProject
bun run start:server
```

「服务启动成功」（サービスの起動成功）と表示されたら、サーバー自身から `http://127.0.0.1:3000` にアクセスできます。上記のコマンドはフォアグラウンドで動作し、`Ctrl+C` で停止します。OS 起動時の自動起動やプロセス管理が必要な場合は、[Bun の systemd デプロイガイド](https://bun.sh/guides/ecosystem/systemd)を参考にしてください。作業ディレクトリをリポジトリのディレクトリに設定し、起動コマンドは Bun の絶対パスに `run start:server` を続けたものにします。そのディレクトリの読み書き権限を持つユーザーで実行してください。

</details>

### 4.4 アクセスとデータについて

- 現在のサービスは固定ポート `3000` を使用し、アプリの画面と API に独立したログイン認証はありません。サーバーにインストールする場合は、ファイアウォールやセキュリティグループでポート `3000` への接続元を制限してください。インターネットに公開する場合は、認証付きのリバースプロキシが必要です。
- 個人でリモート利用する場合は、自分のコンピューターで `ssh -N -L 3000:127.0.0.1:3000 用户名@服务器地址` を実行します（`用户名@服务器地址` は実際のユーザー名とサーバーアドレスに置き換えてください）。接続を維持したまま `http://127.0.0.1:3000` を開けば、サーバーのポート `3000` をインターネットに公開する必要はありません。
- 直接インストールした場合、設定、プラグイン、ワークスペースは既定でリポジトリ内の `data/` に保存されます。Docker ではデータボリューム内の `/app/data/` に保存されます。移行やバックアップでは、このデータをすべて保持してください。画面を開いたらサーバーのワークスペース内にある `myProject` を選択します。プロジェクトを追加する場合は、対応する `workspaces/` 配下にサブディレクトリを作成できます。
- どちらのインストール方法にもシステムの FFmpeg が含まれます。モデルサービスの API Key は、別途画面から設定する必要があります。
